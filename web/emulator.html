ESP32 · S3 · C3 · C6 — Xtensa and RISC-V

Real ESP32 firmware.
In your browser.

esp32sim is an instruction-level emulator for Espressif's ESP32-S3, C3, C6 and the classic ESP32, written in Rust. It boots the real mask ROM, the real bootloader and an unmodified application image — here in this tab, or on your command line as a hardware test bench that a coding agent can drive.

For coding agents

A board the agent can run a thousand times.

Agents write embedded code well and test it badly: a board on a desk cannot be scripted, read back or reset from a shell. esp32sim can. It is the same emulator as the demos above, as a command-line tool any agent with shell access already knows how to use.

  1. Build the firmware as usual.ESP-IDF, PlatformIO or Arduino, unmodified. The emulator boots the real ROM and bootloader, so the app is the one that would go on the board.
  2. Run it with a script.Touches, button presses, encoder turns, GPIO levels and serial input at exact emulated times, with a run limit so the command always returns.
  3. Read the evidence.Console text on stdout, the display as PNG, audio as WAV, GPIO and interrupts as VCD, block coverage, profiles, interrupt latency — files a program can check.
  4. Fix, run again.The same input gives the same run, down to the instruction count, so a failing check stays failing until the fix is real. The project's own golden tests pin console text, WAV hashes and instruction counts.
CLI reference action scripts boards peripherals releases
the loop, from a shell
# build as always
$ idf.py build

# run it 8 emulated seconds with a script of touches, keep the display
$ esp32sim --board waveshare-lcd4b --boot rom \
    --bootloader build/bootloader/bootloader.bin \
    --ptable build/partition_table/partition-table.bin \
    --app build/app.bin --elf build/app.elf \
    --script test/swipe.txt --max-seconds 8 \
    --tft-png panel.png --vcd gpio.vcd --coverage-file cov.txt

# test/swipe.txt — one action per line, at emulated seconds
3.0  touch 450 240 1      # press near the right edge
3.1  touch 300 240 1      # drag left …
3.2  touch 100 240 1
3.3  touch 100 240 0      # release: the panel swipes to its next page
8.0  stop

Point an agent at docs/cli.md and a board name. Runs are single-process with no daemon and no device, so they parallelise like unit tests, and --no-jit is the oracle when a result looks wrong.

What's inside

Software that behaves like the chip.

Four SoCs across both of Espressif's CPU architectures. Most of the SoC model is shared; only the CPU crates are separate. The numbers are from the README and its tests.

Your own firmware

Boot your build in this tab.

Choose the chip and board, pick your bootloader, partition table and app (or a whole flash image), add ELF symbols and a script if you like, and boot. The mask ROM comes from this site; files stay in the browser; nothing is uploaded. On your own machine, the quick start does the same from a release tarball in three steps.
