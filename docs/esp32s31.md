# ESP32-S31

`esp32s31` runs on `esp_soc::Machine` / `Soc` (same path as C3/C6/P4) and is
registered as `--chip s31` / the `esp32sim-s31` binary. It models a bounded S31
peripheral subset through two functional HP harts. It is not a browser backend
or board product, and does not provide a product framebuffer. The scope proposal
is [#319](https://github.com/mikroverk/esp32sim/issues/319).

The implementation was developed in the
[`zhuzhe1983/esp-online-tester` fork](https://github.com/zhuzhe1983/esp-online-tester/tree/58f84135e18c5902e93f33548e0b4bd1e503b4e3/esp32s31).
It is not a source port of Espressif's binary emulator.

## Contract and source versions

The base register source is ESP-IDF v6.1 revision
`fff9895c82d744c7237be8847347bdd1b07c6643`. The later security-clock header layout
also cites revision `274d7ebeaf15cf397347877c34816ea9470d153f`; those differences
are called out in the relevant model. Code comments name the register/header
behind each block. None of these models is silicon-qualified by this contribution.

S31 is not a P4 board alias. Its principal windows are:

| Region | Address interval |
| --- | --- |
| HP SRAM | `0x2f000000..0x2f080000` |
| LP SRAM | `0x2e000000..0x2e008000` |
| ROM | `0x2f800000..0x2f850000` |
| Flash virtual addresses | `0x40000000..0x44000000` |
| PSRAM virtual addresses | `0x50000000..0x54000000` |
| UART0 | `0x2038a000` |

The shared RV32 core supplies its RV32IMAFC subset, counters and standard CLIC
CSR placement (`mintstatus=0xfb1`, `mintthresh=0x347`). S31 custom PIE/HWLOOP
instructions and a complete ISA implementation remain absent. P4's existing
CLIC register/arbitration code is extracted into `esp-periph::clic`; its legacy
and rev >= 3 configuration and behavior remain separate from S31's address map.
S31's interrupt matrix requires an explicit machine-mode PASS_LEVEL.

Two harts interleave through `esp_soc::Machine`. Shared atomic memory, stall/reset
controls and interrupt delivery are functional; this is not measured parallel
execution, bus arbitration or cycle-accurate timing.

## Implemented subset

| Area | Exercised behavior | Boundary |
| --- | --- | --- |
| SRAM, ROM, CPU startup | Mask-ROM load (`Machine::load_rom` / `load_mask_rom`), Flash-MMU `--boot app`, two-hart reset/entry, shared atomics | No instruction substitution; no complete reset-domain machine |
| Interrupts | Local CLIC/matrix (169 sources, dual-core; same choice as S3/P4), UART/USB/timer sources | Modeled sources only; source 152 (EFUSE) outside DeviceSet's 128-bit status |
| UART / USB / timers / eFuse | Shared DeviceSet IP: UART0, Systimer, UsbSerialJtag, TimerGroup, S31 Efuse | No USB enumeration or physical UART/USB timing |
| Flash and PSRAM | Explicit NOR commands/identity/SFDP, erase/program, MMU windows, serial PSRAM and AXI gates | Caller-supplied arrays; functional caches, no cache-line timing |
| Clock/reset/power | XTAL/CPLL/MPLL controls, gated domains, timer counting, watchdog/reset/brownout | Missing analog/clock inputs remain missing |
| GPIO | Local pads / IO_MUX / LP+HP hold — shared `Gpio` blocked (ENABLE@0x34, IN@0x64, PIN@0xf4, OUT_SEL@0xaf4, 62>57 pins + hold coupling); see `pads.rs` | No complete peripheral pin matrix |

Unknown accesses and missing required inputs report a typed fault with the guest
PC. Recognized controls do not imply that every register in the same block works.

## CLI

```sh
# Exact hello path (ROM + IDF v6.1 images from tools/fetch-s31-firmware.sh):
esp32sim-s31 --boot rom \
  --rom path/to/esp32s31_rev0_rom.elf \
  --bootloader esp32s31/firmware/s31-hello-bootloader.bin \
  --ptable esp32s31/firmware/s31-hello-ptable.bin \
  --app esp32s31/firmware/s31-hello_world.bin \
  --max-insns 8000000000
# Equivalent: esp32sim --chip s31 --boot rom ...
# App-only (skip mask ROM, Flash MMU map): --boot app
# ROM also via tools/fetch-rom-elfs.sh DIR (esp32s31_rev0_rom.elf, esp-rom-elfs 20260528).
```

Default flash is 2 MiB with `BoardInputs::hello_w25q16` (JEDEC `0xef4015`) and
strap `0x10` (SPI_FAST_FLASH_BOOT). Override with `--flash-mb`, `--strap`.

## IDF hello_world

**Upstream acceptance target:** ESP-IDF **v6.1** `hello_world` built with
`idf.py --preview set-target esp32s31`, run through `--chip s31 --boot rom`
(or `esp32s31::Machine`). See `tools/fetch-s31-firmware.sh` and
[the contribution receipt](evidence/s31-upstream/README.md).

`Cpu::new_esp32s31` defaults `ext_ill_all_fp` so FS-Off FLW/FSW set
`EXT_ILL.FPU`, matching IDF v6.1 S31 (and P4 rev ≥ 3) lazy-FPU handling.
Observations that informed the default came from the **Apache-2.0**
Espressif esp-emulator 0.51.0 used as an observable oracle only (no source port).
Legacy SPI0 length words used by the 20251218 mask ROM are enabled automatically
when the ROM image is loaded (no CLI flag).

Golden (ignored by default):

```sh
tools/fetch-s31-firmware.sh
S31_ROM_ELF=…/esp32s31_rev0_rom.elf cargo test -p esp32s31 --release --test hello_golden -- --ignored
```

The public ROM is from Espressif's
[20260528 ROM ELF archive](https://github.com/espressif/esp-rom-elfs/releases/download/20260528/esp-rom-elfs-20260528.tar.gz)
(Apache-2.0). Archive SHA-256
`caa463d3cbef2430a5a35847c1d9f2f152403b17a802050927ff60c8da54fe46`;
`esp32s31_rev0_rom.elf` SHA-256
