# ESP32-S31 standalone bring-up

`esp32s31` is moving onto `esp_soc::Machine` / `Soc` (same path as C3/C6/P4). `Bringup` remains a temporary fixture runner until that path boots IDF hello_world.
It executes a bounded S31 peripheral subset through two functional HP harts. It is
not registered as a `--chip` option, browser backend or board, and does not provide
a product framebuffer. The scope proposal is [#319](https://github.com/mikroverk/esp32sim/issues/319).

The implementation was developed in the MIT-licensed
[`zhuzhe1983/esp-online-tester` fork](https://github.com/zhuzhe1983/esp-online-tester/tree/58f84135e18c5902e93f33548e0b4bd1e503b4e3/esp32s31).
It is not a source port of Espressif's binary emulator. This contribution retains
the standalone model and its source-built fixtures, without the fork's product UI.

## Contract and source versions

The base register source is ESP-IDF v6.1 revision
`fff9895c82d744c7237be8847347bdd1b07c6643`. The later security-clock header layout
also cites revision `274d7ebeaf15cf397347877c34816ea9470d153f`; those differences
are called out in the relevant model. Code comments name the register/header
behind each block. None of these models is silicon-qualified by this contribution.

S31 is not a P4 board alias. Its principal windows are:

| Region | Address interval |
| --- | --- |
| HP SRAM | `0x2f000000..0x2f080000` |
| LP SRAM | `0x2e000000..0x2e008000` |
| ROM | `0x2f800000..0x2f850000` |
| Flash virtual addresses | `0x40000000..0x44000000` |
| PSRAM virtual addresses | `0x50000000..0x54000000` |
| UART0 | `0x2038a000` |

The shared RV32 core supplies its RV32IMAFC subset, counters and standard CLIC
CSR placement (`mintstatus=0xfb1`, `mintthresh=0x347`). S31 custom PIE/HWLOOP
instructions and a complete ISA implementation remain absent. P4's existing
CLIC register/arbitration code is extracted into `esp-periph::clic`; its legacy
and rev >= 3 configuration and behavior remain separate from S31's address map.
S31's interrupt matrix requires an explicit machine-mode PASS_LEVEL.

Two harts interleave one interpreter instruction at a time. Shared atomic memory,
stall/reset controls and interrupt delivery are functional; this is not measured
parallel execution, bus arbitration or cycle-accurate timing. Optional RTC,
calibration and SYSTIMER advancement from nominal CPU cycles is explicitly enabled
by the caller. Other clock domains can be advanced through their own input APIs.

## Implemented subset

| Area | Exercised behavior | Boundary |
| --- | --- | --- |
| SRAM, ROM, CPU startup | Checked ELF loading, ROM initializer reconstruction, two-hart reset/entry, shared atomics | No instruction substitution; no general image loader or complete reset-domain machine |
| Interrupts and observations | CLIC/matrix, UART/USB/timer sources, real guest ISRs, cache/PSRAM/bus error reporting | Modeled sources only; no full interrupt fabric or supervisor mode |
| UART and USB console | FIFO/status, clocks, RX interrupts, explicit USB packet peer | No USB enumeration or physical UART/USB timing |
| Flash and PSRAM | Explicit NOR commands/identity/SFDP, erase/program, MMU windows, serial PSRAM and AXI gates, guest execution/readback | Caller-supplied arrays and die responses; functional caches, no cache-line timing or inferred product capacity |
| Clock/reset/power | XTAL/CPLL/MPLL controls, gated domains, timer counting, explicit watchdog/reset/brownout inputs, bounded PMU/APM/PMS policy | Missing analog/clock inputs remain missing; no measured oscillator, voltage or full power policy |
| GPIO and eFuse | Software GPIO/hold/input subsets, explicit unresolved-pad levels and decoded eFuse read image | No complete peripheral pin matrix, OTP programming, identity or security profile |
| SHA, entropy and keys | Guest SHA verification, gated deterministic TRNG CRC path, crypto clock roots, cold key-manager reset policy | No physical entropy guarantee or successful cryptographic key operations |

Unknown accesses and missing required inputs report a typed fault with the guest
PC. Recognized controls do not imply that every register in the same block works.
The development example stops at the first unsupported access; its optional
bounded exception execution resumes the guest at its architectural trap vector.

## Reproduce source-built fixtures

Use a RISC-V compiler supporting `rv32imafc_zicsr` and esptool 5.4.0 with S31
image support. Outputs belong in `target/`, not in the source tree:

```sh
S31_BUILD_ROM_IMAGE=1 ESPTOOL_BIN=/path/to/esptool \
  RISCV_TOOLCHAIN_PREFIX=/path/to/riscv32-esp-elf- \
  bash examples/s31-bringup/build.sh target/s31-fixtures

python3 tools/s31-fixture-test.py --fixtures target/s31-fixtures \
  --rom /path/to/esp32s31_rev0_rom.elf

cargo run --release -p esp32s31 --example bringup -- \
  target/s31-fixtures/probe.elf A
```

The public ROM is from Espressif's
[20260528 ROM ELF archive](https://github.com/espressif/esp-rom-elfs/releases/download/20260528/esp-rom-elfs-20260528.tar.gz).
Archive SHA-256 is
`caa463d3cbef2430a5a35847c1d9f2f152403b17a802050927ff60c8da54fe46`;
the `esp32s31_rev0_rom.elf` SHA-256 is
`a52ad7513deb656a910a5740125f1cce2c7941f11ce57213b7b43aea93d5ab87`.
ROM and generated firmware bytes are not committed. The loader reconstructs
omitted ROM-side initializer bytes from that same ELF's explicit RAM sections;
the guest's own unpack loop still executes.

The [fixture guide](../examples/s31-bringup/README.md) explains each program and
its positive/negative controls. Tests needing these local builds are named
`external_*` and ignored by default. The helper sets their input paths and runs
them explicitly; ordinary CI still runs the hermetic S31 tests using the existing
`--include-ignored --skip external_` policy.

## Real firmware progression and limits

**Upstream acceptance target:** ESP-IDF **v6.1** `hello_world` built with
`idf.py --preview set-target esp32s31` (and matching bootloader/partition table),
run through `esp32s31::Machine` (`esp_soc::Machine<S31>`). Do **not** treat the
fork's Metalio INK4 Plus product image as golden or as a merge gate. This Mac
worktree currently has IDF 5.3/5.4 only, so hello_world is **not** claimed here;
see `tools/fetch-s31-firmware.sh` (stub) and
[the contribution receipt](evidence/s31-upstream/README.md).

`esp32s31::Machine` is the review path (Soc/SocBus). `Bringup` remains a
temporary fixture runner for hermetic unit/external probes until Machine boots
that hello_world. SRAM/ROM-linked ELFs load and step today; flash-MMU `--boot app`
still returns a clear error until mapping is finished.

Historical fork notes (not acceptance): a pinned Metalio INK4 Plus 2.0.68 image
reporting ESP-IDF `v6.1-dirty` was used during bring-up exploration and, with a
fully declared development profile, reached ROM Flash verification, the original
bootloader, OTA metadata writes, both application harts, the PSRAM test and early
application/Flash initialization. That is not a complete board boot or proof of
the physical product's Flash/PSRAM/analog configuration, and it is superseded as
an upstream bar by IDF v6.1 hello_world.

`Cpu::new_esp32s31` defaults `ext_ill_all_fp` so FS-Off FLW/FSW set
`EXT_ILL.FPU`, matching IDF v6.1 S31 (and P4 rev ≥ 3) lazy-FPU handling in
`vectors.S`. That policy was previously behind an opt-in bring-up switch; the
switch is removed. Observations that informed the default came from the MIT-
licensed Espressif esp-emulator 0.51.0 used as an observable oracle only (no
source port). A remaining bring-up compatibility choice:

- `--rom-spi0-shadow` enables an observed legacy ROM register-length convention
  that differs from the public header map. It is disabled by default.

With the declared boot profile the product image still hits missing PMU
initialization after FPU setup. Display, touch, radio/networking and the rest of
the board remain unimplemented.

`tools/s31-native-firmware-probe.py` accepts a caller-supplied URL and SHA-256,
verifies the download in memory, and passes the bytes to the runner without saving
a firmware file. Its JSON output can include raw UART/diagnostics; keep it under
`target/` and curate it before publishing. Run `--help` for the explicit clock,
analog, pad, NOR, PSRAM and exception-budget inputs. There are no product defaults.

Current-upstream checks, exact inputs, compact observations and CPU samples are
retained in [the contribution receipt](evidence/s31-upstream/README.md).
