# LILYGO 首批产品接入

本次接入 6 款 ESP32 产品。目录中的接入顺序参考公开关注度；它不是销量排名，也不表示覆盖了 LILYGO 全部产品。工作台继续按厂商筛选、按名称排列，所有设备沿用同一个场景、分享和嵌入协议。

[产品顺序与后续队列](research/lilygo-priority-2026-10-28.md)记录了关注度来源；[目录与固件审计](research/lilygo-catalog-audit-2026-10-28.json)保留每款产品的出厂固件调查和校验数据。

## 固件入口

选择 LILYGO 设备后，固件库默认选择有依据的官方出厂镜像。二进制由浏览器直连固定的官方远程地址，本站只保存元信息。布局、芯片、容量和 SHA-256 核对通过不代表全部外设已经模拟；未验证镜像保留试运行状态，没有板级模型的设备显示“尚未完成适配”。

在“远程地址”的来源选择框中选择 **LILYGO Spark**，位置与 M5Stack 的 Burner 相同。可按当前型号搜索项目和选择版本；已确认的 BIN 使用原有下载、验证、运行和历史记录流程。只有 ZIP 的条目提供来源说明，不把压缩包当作完整镜像运行。

Spark 官方配置中的 OSS 端点本轮未提供本站所需的 CORS 响应头，因此使用其官方 GitHub 仓库内可跨域读取的清单。界面展示该清单的日期；它可能落后于桌面 Spark 的线上数据。上游标签中存在跨型号混挂，本地匹配还会核对具体产品、仓库路径或文件名。没有匹配项时保留手动 HTTPS 和本地固件入口。

[Spark 来源与 CORS 审计](research/lilygo-spark-cors-2026-10-28.md)列明清单地址、时间、摘要及每个型号的匹配边界。本轮真实浏览器从本站源成功读取官方清单（生成日期 `2026-06-26`），并取得 T-Display-S3 的两个项目；这项检查只读取元信息。

开源项目仍加入原有平铺共享的 `firmware-watchlist.json`，不另建 LILYGO 专用列表。项目支持的设备、镜像格式和自动同步规则分别核对，不因为同为 ESP32 而互换固件。

## 验证方法

`tools/platform-lilygo-runtime-test.mjs` 通过公共产品定义、平台 runtime 和真实 WASM worker 启动原有 MicroPython 价格屏测试。它检查固件绘制的 135×240 framebuffer，并通过固件读取 GPIO 验证两个按键的按下、释放、组合键及暂停后释放。此测试固件仅用于回归，不冒充出厂固件，也不进入公共固件目录。

原版 TTGO 的官方出厂镜像也在真实浏览器中尝试运行：SHA-256 为 `85a2598f363a96c4d4eb4aebad5af81c286653eab0d20543110546e4d2c7b9ed`，从 ROM 启动、不使用 stub 或应用直启，串口输出 `Start`，并绘制真实启动 Logo。但随后约每 1.675 客体秒发生 `RTCWDT_RTC_RESET`，观察到持续复位。该镜像仍为未验证 trial，不能称为稳定兼容。保留这一失败结果，不用价格屏测试替换出厂默认项。

目录检查使用 `python tools/validate-platform-catalog.py`；平台回归使用 `node --test tools/platform-*-test.mjs`。UI 检查包括厂商切换、Spark 搜索与版本选择、3D/2D、外壳材质、分享及嵌入页。未进行真实设备刷写或实机对比。

本轮 105 项平台测试、目录 schema 与证据隐私检查通过。真实浏览器检查了 6 款的出厂默认项及运行按钮边界、4 套模型加载、Spark 搜索和选择版本、尚未运行的选择分享、iframe 源/hash 还原、2D/3D 切换和外壳原色/金色/紫透。未验证远程源的 mini 自动启动会先确认，取消时没有固件下载；原版 3D 上下两个按键分别命中 GPIO0/35，并由 MicroPython 固件读取确认。结果见 [集成回执](evidence/lilygo-integration/receipt.json)。
