# LilyGO P4 空闲路径与代码生成调查 — 2026-11-22

**状态：本轮局部调查及拒绝候选证据已齐全；P4 回退未修复，发布认证尚未完成。** 本文把集成候选的计时结果、静态代码生成观察及后续各候选分开记录。`91d7975` 的 P4 用户 CPU 中位数增加 **7.2249%**，八轮全部较慢；独立的 `Box<I2c>` 候选测得 **+20.8405%**，组合内联候选测得 **+9.3914%**，各四轮全部较慢，均已保存证据并撤回。单层 wrapper 内联未实现预定代码生成目标，没有采样。本轮局部优化已停止，最终 Rust 源码恢复原始集成候选内容，保留已知原生 hello 开销；不能写成已修复、无回退、性能通过或发布完成。

本调查沿用 [EX220](../../experiments.md#ex220) 的冷状态／缓存字／布局调查和 [EX212](../../experiments.md#ex212) 的空闲布局与代码形态先例，不另立实验编号清单。P4 hello 是本次集成新增的性能负载；这些先例不证明本次回退具有相同原因。

## 基线与原始集成候选

基线为 `573f5a6c1bcc6dbf0388383d178a3935ec8ddcce`；集成候选为 `91d79752519b329c76912370d900d14a3bba0ad4`。两者 Rust／Cargo 源码摘要、可执行文件哈希及公共输入已固定在最终计时收据中。

P4 使用既有 rev0 mask ROM、公开 bootloader、分区表与单核 hello，2 MB Flash／0 MB PSRAM，运行 30.000 秒模拟时间。每版一次预热后完成八轮 AB／BA 交替测量；所有 18 次运行的工作量与输出一致：core0 **10,800,000,000** 条指令、core1 0，**10,800,000,000** 周期、0 异常、3,031 中断，stdout SHA-256 为 `3d24ec4ac730ed8f8843eda1997dea9cf115707ce7832196076a8a6730842be5`。

## 静态代码生成观察

原始代码生成审阅使用 x86-64 release ELF：

| 对象 | 字节数 | SHA-256 |
|---|---:|---|
| 基线 P4 ELF | 34,395,752 | `fc78b69e754d68bf220f85c6f781b43697774c1c13b2978e2c3f9dc7a20c19ef` |
| `91d7975` P4 ELF | 36,223,496 | `93fa35675f31b430c436a57f43ea1e044fdb6b8e64f2fe1de30e297c369c2bf9` |

审阅保留了完整函数名，逐函数反汇编并规范化地址。下表“静态指令”包括对齐指令及冷 panic 路径，不是动态执行数，也不代表指令耗时。

| 函数 | 基线／候选字节数 | 基线／候选静态指令数 | 观察 |
|---|---:|---:|---|
| `SocBus::refresh_irq` | 766 / 766 | 209 / 209 | 23 处内存位移增加 184 字节；两版都调用独立的 `Peripherals::source_status`。 |
| `Peripherals::tick` | 1,308 / 1,308 | 287 / 287 | 65 处位移增加 184 字节；调用次序相同，另有诊断常量重定位。 |
| `Bus::tick` | 4,544 / 4,544 | 985 / 985 | 96 处位移增加 184 字节；还有一个地址运算立即数增加 184，直接／间接调用次序相同。 |
| `SocBus::next_deadline` | 1,170 / 1,170 | 295 / 295 | 14 处位移增加 184 字节。 |
| `SocBus::periph_read` | 462 / 462 | 120 / 120 | 13 处位移增加 184 字节。 |
| `Peripherals::source_status` | 1,293 / 1,219 | 327 / 304 | 两版均外联；候选的聚合与寄存器分配形态改变，函数整体反而更小。 |
| `DeviceSet::pre_access` | 793 / 1,119 | 211 / 286 | 候选额外保存／恢复一个寄存器并复制 self 指针；新 GPIO 路由调用仍位于 I2C0 地址／配置分支内。 |

新增可选 I2C0 中断源 44 使用可选来源缓存字 1 的 bit 12；原有 USB_OTG 源 93 使用字 2。候选 `source_status` 末尾用 SIMD 合并字 1 与字 2，但函数其他部分的分支、算术和寄存器分配也变化，因此不能把新增尾部逻辑等同于固定的净动态指令增量。

P4 原有 `Bus::tick` 返回 1，`Machine::after_round` 因而每个调度 round 都调用 `refresh_irq`；这一调用并不以 I2C0 是否活动为条件。**审阅没有发现原本内联的 `source_status` 因本次改动首次变成外联：基线与原始候选都已有外联调用。** 只能说布局和聚合代码形态有变化，不能据此证明其造成了全部或某个比例的 CPU 回退。

保持语义的边界同样来自既有实现：不能仅因 `active_optional` 为空就跳过可选中断缓存聚合，因为 I2C 控制器完成后可以停止活动而仍保留待处理完成中断。独立 I2C0／I2C1 时钟、地址路由、可选激活、deadline 和 pending IRQ 行为均需保留。相关语义背景见 [EX216](../../experiments.md#ex216)。

## 已撤回的 Box 候选

## 已撤回的组合内联候选：目标实现，计时仍偏慢

## 最终保留版本与调查结论

本轮局部优化已停止；调查结果、拒绝候选、代码生成观察和全部正式样本已经保存。撤回后的最终 HEAD 为 `9d4239fc514865838e9cca9a2f06917addebc7d0`，重新计算的 **646 个 Rust／Cargo 文件**摘要为 `5ac573ea50f2f00324edf84b3ddb8a03863069cdd33b11540a8cf818066f3935`，未提交 Rust 文件为空，与原始 `91d7975` 集成计时源码完全一致。原始实测的四个原生 ELF 已恢复，SHA-256 分别与最终集成性能收据相同；验证证据见 [集成验证记录](lilygo-integration-verification-2026-11-22.json) 的 `finalSourceVerification`。

因此，原集成源码对应的原生及 WASM 功能记录仍对应最终 Rust 内容；撤回和恢复不是新增性能改进，也不是新的计时采样。最终保留 **P4 原生 hello +7.2249%** 的已知开销和 **S3 +5.3481%** 的未解释正增量，不能称已修复或无性能回退。该原生 P4 比例不能外推成浏览器／WASM 也慢 7.2%，更不代表所有 P4 产品、固件或交互的耗时比例。

局部调查完成与发布认证完成是不同结论：本轮候选均已作出处置，**发布认证仍未完成**。

## 环境、解释与证据边界

原始集成、Box 和组合内联三个已经完成的计时比较均使用同一稳定工具链和 release 配置；采样时没有有意并发的工作区构建、测试、模型转换或其他基准。它们仍运行在共享 Linux x86_64 虚拟机中，未控制或观测 CPU 亲和性、物理温度、频率及宿主机其他租户负载。各自完整的用户／系统 CPU、墙钟、运行前聚合负载和原始样本均保留在对应 JSON。

[EX220](../../experiments.md#ex220) 的既往案例区分了缓存来源字与布局变化，并保存了冷状态调整前后的负面及后续测量；[EX212](../../experiments.md#ex212) 说明相似代码形态在不同机器与不同构建产物间需要独立验证。它们支持检查布局和调用链这一调查方向，不能直接推出“本次是缓存行／内联造成”或“Box／inline 一定有效”。当前没有主机硬件计数器证据来确认缓存未命中、分支预测或已退休主机指令的变化。

此前只有 S3／C3／C6 的 [早期测量](lilygo-performance-2026-11-22.md) 与这里的 P4 负载及候选不同。应保留其 C3 +5.2723% 和 C6 五对全部较慢的历史结果；不能借后续候选、不同负载或不同运行条件解释掉旧结果。本轮结论为：原始 P4 回退未修复；Box 和组合内联均已测量、拒绝并撤回；单层 wrapper 的目标未实现且未采样。最终恢复原始集成 Rust 内容，局部优化结束，已知开销与测量限制保留。
