# 参考硬件验证与实施顺序

第一阶段先证明 **StopWatch 固件 → CPU → 屏幕/输入 → UART GPS → 固件反应** 的闭环，再做完整 3D 产品体验。所有下述测试均为待执行计划，本轮只完成上游代码和 WASM API 核查。

## 选型门槛

| 阶段 | 交付 | 通过条件 | 失败后的处理 |
| --- | --- | --- | --- |
| G0 后端 | 固定 commit 的 WASM、ROM、最小 S3 测试固件 | 普通静态 HTTP 服务下完整启动；无外部运行服务器；资源和日志可复现 | 先定位芯片/镜像/浏览器问题，不建设大量 UI |
| G1 StopWatch | 板型适配、2D 帧输出、A/B 键、触摸 | 与同一测试固件的硬件输出一致；确认显存裁剪、方向和按键线路 | 缺少器件模型则补模型并记录边界 |
| G2 GPS | 可组合 UART 配件、轨迹回放、供电连接模型 | 固件从指定 UART 收到真实 NMEA 字节；断线、无定位和恢复有对应反应 | 若缺 UART 路由则扩展后端，不能注入调试控制台代替 |
| G3 PaperMono | SSD1677、FT6336G、必要 M5PM1/M5IOE1 行为 | 实际显示命令形成对应画面；BUSY/复位和按键触摸用例通过 | SD/NFC/LoRa 等按固件依赖逐项加入 |
| G4 网站 | 三库、3D、个人编辑器、远程加载、分享 | 纯静态托管；新浏览器能还原分享配置；CORS 失败有上传退路 | 保留能力标签，不扩大兼容性声明 |
| G5 Agent | 稳定 API、skill、无头测试和 PR 验证 | 同一场景可由 UI 与 agent 执行，并产生可比较的报告 | 接口版本或缺能力时给出明确失败 |

G0 到 G2 应当先于大规模建库和精细建模。esp32sim 是当前首选实验对象；若其具体固件不兼容，先记录可复现问题，再评估上游修复、适配器或其他后端。esp-emulator 只有补齐所需接口后，才参与整机交互验收。

## StopWatch 与 GPS 测试夹具

先写一份小型、可公开的板级测试固件：启动串口日志、屏幕四角/色条/圆形边界、A/B 键计数、触摸坐标、GPS 数据解析。GPIO、UART 控制器和串口参数在构建元数据中固定；同一份 merged image 在模拟器和用户硬件上运行。

StopWatch Grove 官方信号为 G10/G11。初始测试可以选择 UART1 的可用映射，但最终 RX/TX、线序和供电使能要以固件及实物核对结果为准。文档中的 `PORT.C` 指 GPS 的常见连接用途，不能直接套用旧款 M5Core 的 GPIO16/17。测试场景中 UART controller 与 pin route 分开记录。

GPS 先保留 U032/9600 和 U032-V11/115200 两个变体，实际测试前根据外壳型号或设备识别确认用户持有哪款。不会通过自动改波特率掩盖配置错误。串口位时序如果后端未建模，要标成限制，不能把波特率不敏感的测试视为电气验证。

| 用例 | 输入 | 验证证据 |
| --- | --- | --- |
| 无定位启动 | 有合法 NMEA，定位标志无效 | 固件显示未定位，不能误报 0,0 为有效位置 |
| 获得定位 | 固定 UTC、坐标、高度和卫星信息 | 接收字节、解析日志、屏幕内容相符 |
| 移动轨迹 | 带时间戳的位置序列，正确单位和校验和 | 位置/速度/方向更新，路径回放可重复 |
| 失联 | 停止 UART 输出 | 固件按自身超时变旧/失效，前端不替它作判断 |
| 恢复 | 恢复合法数据流 | 应用恢复显示，状态机无卡死 |
| 错误帧 | 错校验、截断、分片、超长行 | 解析器忽略或报告错误，并能处理后续正常帧 |
| 断电/拔插 | 关闭外设电源域或移除连接 | GPS 不再产生可达字节；重新上电后按模型启动 |
| 控制命令 | 固件向模块 TX 发配置 | 已支持命令有应答；未实现命令明确记录，不能全部 ACK |

RMC/GGA 等句子由协议实现生成并计算校验和，时间使用 UTC；GPS 字段的十进制度、度分格式、节和米/秒要显式转换。设备行为是卫星定位输出的功能模拟，不模拟射频接收、城市峡谷精度或真实冷启动性能。

## PaperMono 测试夹具

测试以 SPI2 屏幕命令、RAM 内容、BUSY 引脚、IO 扩展器复位和电源顺序为依据；显示最终图像是其中一项证据。验证黑白/灰阶图、窗口更新、旋转、全刷/局刷、连续刷新、断电后画面保持。屏幕残影与波形寿命留给实物检验，合成刷新动画不作为物理精度证据。

官方 PinMap：SSD1677 MOSI14/CLK15/CS16/DC17/BUSY18；FT6336G 位于系统 I²C SDA47/SCL48，地址 0x38，INT4；按键 A/B 为 GPIO2/3。M5PM1 和 M5IOE1 负责额外复位/供电。实际 driver 对控制器编号、有效电平和时序的要求仍需与原理图、驱动源码核对。[官方资料](https://docs.m5stack.com/en/core/PaperMono)

先用最小固件独立验证这些路径，再运行官方示例或 CrossPoint。后者可能依赖 microSD、RTC、电量和其他初始化，因此“屏幕已能画图”不保证阅读器可以完整启动。

## 自动化证据

每份报告记录固件与引擎哈希、所有模型版本、配置、仿真时间、随机种子、输入事件和失败分类。保留串口日志、关键总线事件、原始 framebuffer、3D 截图及所执行断言。

功能测试直接检查真实 framebuffer/串口/寄存器事件；3D 截图用于验证可视化和点击映射。不要用 3D 截图替代固件是否执行的检查。UI 自动化默认无头运行，使用项目测试专用浏览器并在 `finally` 中关闭；CLI 会话遵循仓库 AGENTS.md 的 wrapper 生命周期规则。

使用仿真时钟安排长按和 NMEA 帧，设置有限的仿真时间与墙钟超时。固定初始 Flash、RTC、随机数和网络输入；如果当前后端不能控制随机数或时间源，报告必须说明重放是尽力而为，不能声称确定性完全一致。

实机对照由用户已有硬件完成：校对相同输入下的画面、事件顺序、可见状态和串口结果。仿真通过不认证 Wi-Fi/BLE/LoRa 射频、USB 电气行为、功耗、音质或精确实时性。

## 本轮尚未验证的事项

- 两款设备任一用户固件的完整启动和运行。
- esp32sim 的浏览器构建、StopWatch＋GPS 组合，以及 PaperMono 板型实现。
- 用户 GPS Unit 的代次及实际接线。
- 特定远程固件 URL 的浏览器 CORS、镜像格式和许可条件。
- 网站部署、可分享 URL、项目 API、DIY 编辑器与自动化执行。

下一步可以直接从 G0/G1 开始；第一项实际验收不是 3D 外壳，而是 StopWatch 的固定固件在静态网页里显示一帧可核对的真实输出。
