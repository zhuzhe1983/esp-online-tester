# LilyGO 模型扩展：2026-11-22

本轮保留已有 5 个模型，为其余 122 个产品添加本地可加载模型，LilyGO 类目的模型入口达到 **127/127**。新增资产包括 **26 个采用官方仓库 CAD 的模型、96 个照片衍生模型**；不再有完全无来源的占位模型。所有新增模型仍标记为 `partial`。模型覆盖、物理外观精度、板级模拟和出厂固件兼容是独立结果。

逐产品清单、日期依据、来源、使用范围、未知项和最终几何 hash 见 [结构化报告](lilygo-model-expansion-2026-11-22.json)。顺序沿用 [来源调查](lilygo-adaptation-sources-2026-11-22.json) 的优先级：优先有依据的硬件发布日期；缺失时明确使用商店记录作为代理日期，不把固件更新或资料抓取时间写成发布日。

## 来源选择及仍未完成的工作

本轮检查了 80 个完整官方仓库快照，在 95 个关联仓库的扫描队列中发现 167 个 CAD/footprint 候选文件。另补查原始 AMOLED 与旧版 T5 的准确仓库。完整的候选清单和查询收据见 [CAD 调查](lilygo-cad-discovery-2026-11-22.json)。存在文件只说明候选存在，还须区分版本、壳体单件、摆放版式、局部板层和实际装配。

| 新增模型状态 | 数量 | 当前含义 |
| --- | ---: | --- |
| 已保留官方托管 CAD | 26 | 保留源文件实际提供的几何；不泛化为全版本、全装配或制造精度保证 |
| 照片模型，仍有 CAD 候选待确定适用范围 | 36 | 候选的具体 SKU、版本或装配关系尚未确定；照片模型是临时外观 |
| 照片模型，所检查的完整仓库未见 CAD 候选 | 40 | 结论仅限已检查仓库，不等于网上不存在 CAD |
| 照片模型，CAD 搜索或别名映射仍不完整 | 20 | 精确产品照片已保留；不能把未成功解析的仓库链接写成无模型 |

照片模型不统一宣称为三维重建。T-Dongle-C5、T-Watch Ultra、T-Display Bar 使用官方多角度照片和标注包络尺寸，建立外壳、屏幕及有证据的可见部件；局部圆角、壁厚与内部位置仍是估计。其余照片外观主要采用投影轮廓的凸包挤出，保留其他照片供复核。**这不是摄影测量**，无法从这些投影证明绝对尺寸、深度、遮挡面或内部结构。未标定的投影统一按调试布局使用最长边 60 mm；该数值不作为实物尺寸。

| T7-C6、T-Knob | 保留官方源坐标；T-Knob 排除源文件中单独摆放的 USB 线缆，不把配件范围计入机身 |

| T-Deck Plus 两个商店条目 | 共享明确对应 Plus 外壳的官方 STEP。相同壳体不证明内部硬件或固件相同 |
| 原始 1.91 英寸 T-Display S3 AMOLED | 官方 STEP 没有注明版本；商店存在 V1/V2 按键位置变化，因此只作为版本未标注的参考 CAD |
| Mini E-paper Core、Mini E-paper S3 | 两仓库发布相同的盒壳 STL。模型只代表基础盒壳，不包括 S3 工业手柄/天线组合。原文件约 24.74×38×11.7 mm，官方尺寸图为 24.5×40×12 mm，长度差异保留，不强行缩放 |
| T-Deck Pro | 四份 STL 已有一致装配坐标，只作刚性轴变换。缺少的 35 个键帽在精确壳孔中按照片估计；矩阵语义与原生 240×320 屏幕仅对应 V1.0 HD-V1-250326，不宣称兼容 V2 |
| T3 S3 Meshtastic | 找回精确 Spark 产品的正反面合成照片；仅 256×256，深度和尺度未标定。原生 128×64 SSD1306 的证据链单独保留，不由此推断 PCB 版本或内存 |
| T5 V2.3.1 | 厂商仓库明确关联旧产品并提供 2.13 英寸 STEP，但 CAD 版本及原作者未明确，标为官方托管的参考 CAD。显示仅选择源码明确注明的 DEPG0213BN：可见 122×250、控制器 RAM 128 列；Spark 的 212×104 冲突保留 |

内部没有可靠布局时保留带 `UNKNOWN` 的替换板层，不添加想象的芯片和走线。实体屏幕展示真实帧缓冲；物理窗口位置或旋转未经校准时，使用独立 `LIVE DEBUG` 面板。已验证的板级控制绑定稳定 ID；物理按键位置未知时增加独立 `DEBUG INPUT` 控件，不将其画成实物按键。

## 保留与重建

最终资产约 89.2 MB，其中来源照片约 25.1 MB、无损 CAD 归档约 33.0 MB、几何约 27.1 MB。几何共 1,587,684 个三角形，展开约 114.3 MB；单个文件均通过加载器的大小限制。CAD 模型采用 gzip 保存 float32 位置和法向量，压缩不改变任何位。`build-check.json` 分别记录存储文件与展开几何的 SHA-256。

STEP 使用其原有单位与刚性观察变换；STL 没有固有长度单位，毫米解释及与官方尺寸图的核对分别记录。原始文件、来源照片、抓取收据和可用的上游许可证保留在对应资产目录。没有明确 CAD 授权声明时原样记录，不套用邻近仓库或第三方驱动的许可证。详见 [来源声明](lilygo-model-source-notice.md)。

```sh
python3 tools/sync-lilygo-model-runtime-hints.py --profile-dir docs/platform/research
python3 tools/build-lilygo-expansion-models.py --output web/platform/assets
node tools/verify-lilygo-expansion-models.mjs
python3 tools/report-lilygo-expansion-models.py
```

运行时表面同步器自动发现 `lilygo-*profiles*.json` 中有 `productId`/`boardId` 的条目，纳入后续 S3、RISC-V 和 classic ESP32 适配。它只更新显示语义、独立调试控件及对应来源，断言原始 CAD 定义和 CAD 来源不变。

## 验证范围

导出检查覆盖 122 个新增资产，检查所有坐标/法向量有限、三角形和零件范围有效、来源 hash、展开几何 hash 以及原生帧缓冲纵横比。生产模型加载器完成全部 122 个加载。独立目录离线重建用于核对最终模型 JSON 与几何字节是否可复现。

这些检查证明资产能够被当前加载器读取，不证明全部照片模型达到物理精度，也不证明固件已经运行。实物叠图与内部装配仍有报告中列出的缺项；真实浏览器 WebGL 渲染另由集成/CI 检查，不能由离屏几何投影或 Node 加载测试替代。
