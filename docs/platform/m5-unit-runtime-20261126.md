# M5Stack Unit and Atom controller digital paths

Four former previews now construct independent classic ESP32 boards and execute authored LX6 loads/stores through GPIO, RMT, SPI, I²C and PSRAM MMIO. Original upstream firmware acceptance is recorded separately. U138's independent IP101G wiring is integrated with the shared Ethernet engine and verified by guest MDIO/ARP/DMA and explicit host relay tests.

The K117 button's existing source-derived mesh is bound to the real G39 input; its geometry is unchanged. U120 retains its real framebuffer-bound screen. K115 retains `display: null` in the physical product definition; its runtime image is explicitly an external FPGA-memory observation. PCB, paper, connector calibration and material limitations from prior model reports remain.

Thermal2's five environment inputs are raw ADC counts0…32767, hotspot centerX0…31/Y0…23 and radius0…32. They update the next timed sensor frame, never guest temperatures or an output framebuffer. Runtime, scene schema, shared control form, recording and replay apply this profile independently of StickT2's160×120 Raw14 profile. The virtual EEPROM yields nominal Vdd3.3V and Ta25°C using the original manufacturer's equations; its uniform pixel coefficients are a reproducible test calibration, not a physical sensor dump.

The authored LX6 fixture executes `s32i`/`l32i` for every peripheral operation. It is a digital protocol test, not a compiled manufacturer application or a physical measurement. Receipts, exact source revisions and remote binary headers are in `docs/platform/evidence/m5-unit-runtime-20261126/`. Central019 WASM execution and shared Ethernet tests passed as recorded below. Actual browser UI verification and official V0.7 execution remain separate work.

The integration harness `tools/platform-m5-unit-worker-test.mjs` runs four correct and four incorrect physical-route diagnostic images through the public runtime and actual production Worker/WASM. The original bootloader diagnostics are generated by `tools/fixtures/m5-unit-controller-probe.mjs`, retain real mask-ROM boot and contain no app-direct mode or stubs. U120 diagnostic UART commands are clearly separated from the unimplemented external Grove I²C slave. Set `ESP32SIM_WASM`, `ESP32SIM_ROM_DIR` and optionally `M5_UNIT_WORKER_RECEIPT` to use central build inputs and retain results. Fixture structural/header/checksum/SHA verification and all eight execution runs passed against central019 WASM. Four additional public reset checks start from held-button, green-pixel or changed-ADC states, reboot the real mask ROM, discard old UART/output and return to released/red/default-ADC1000. Receipt `worker-019.json` retains hashes, real guest serial and frame hashes. The two earlier harness-only failures are retained separately; no board behavior was changed to satisfy them. Cloud browser access to the independent local overlay returned ERR_CONNECTION_REFUSED and tab acquisition was blocked by URL policy, as recorded in `browser-attempt.json`; browser DOM/WebGL acceptance is not claimed.

`esp32/tests/unit_poesp32.rs` adds three authored LX6 guest tests for the shared EMAC integration: IP101G MDIO identity and busy timing, complete ARP transmit/default VirtualNet response into RX DMA RAM, physical route/clock/reset negatives, and explicit host wired relay using the same descriptors. All three U138 tests and four shared-EMAC tests passed at integration commit `ba392978`; the same integration passed all-targets Clippy for esp32 and esp-periph. Exact commands and results are retained in `docs/platform/evidence/m5-ethernet-runtime-20261126/checks.json`.

U138 additionally passed `tools/platform-m5-poesp32-worker-test.mjs` against central020 WASM SHA-256 `0cc18d96042c0b2707afbe3b80102cabcbdd6868fccfcc84504cabed8b3179a2`. The public `m5stack-u138` runtime loads the authored `m5-poesp32-probe.mjs` diagnostic as an ordinary Flash bootloader at0x1000; the unchanged production Worker and real classic mask ROM load it into SRAM. Neither stubs nor application-direct startup is enabled. A cold boot and public `reset()` each verify PHY ID0243/0c54 at address1, an absent address2, TX/RX enhanced descriptors, DMA TI/RI and write-one-clear status, and five complete guest ARP exchanges with the independent wired VirtualNet peer. The guest checks every received byte with `l8ui`, prints all46 RAM bytes including the little-endian FCS, and independently calculates CRC32 `4afc196e` from the42-byte ARP reply. Missing MDC23 or MDIO18 yields no PHY identity. Incorrect RMII22, REFCLK0, disabled peripheral clock and asserted PHY reset5 preserve DMA ownership and all48 RX-buffer sentinel bytes; restoring each condition permits a fresh complete reply. Public reset produces one new ROM boot and repeats every check with cleared serial history.

Receipt `docs/platform/evidence/m5-unit-runtime-20261126/u138-worker-020.json` retains actual serial, image/ROM/source hashes and guest CCOUNT samples. The final MDIO polling samples are7630/7645 cycles at240MHz (about31.8µs), within an explicit128-cycle window around the modeled32µs deadline; the last bus-poll timestamp and guest polling are not physical clock-edge measurements. The matching checks receipt preserves the initial missing-`await`, oversized bootloader/partition-table collision rejected by the real ROM, and overly strict timing assertion. The final diagnostic is25888 bytes, with an enforced0x7000 bootloader limit. Set `ESP32SIM_WASM`, `ESP32SIM_ROM_DIR` and optionally `M5_POESP32_WORKER_RECEIPT` to reproduce. This Worker result does not validate ESP-AT/factory firmware, PoE power conversion, wire padding/PHY waveforms, a browser UI, external Internet or the host relay; the latter retains its separate native test above.
