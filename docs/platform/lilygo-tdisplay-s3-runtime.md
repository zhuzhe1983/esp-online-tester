# LILYGO T-Display-S3 非触摸版：显示子集

本型号现在有 `tdisplay-s3` 板级模型，目录状态为 `partial`。官方 **TFT-eSPI 字体演示 20231113** 已在原生模拟器和实际网页 Worker 中正常 ROM 启动并显示不同字体页。它是独立演示，**没有替代出厂默认固件**。

默认的 **非触摸出厂固件 20231013** 和另测的 **LVGL demo 20250109** 仍停在 LCD/GDMA 初始化等待，不能据字体演示的成功声称出厂固件可用。完整设备、实机刷写、休眠唤醒和电池行为均未验收。

## 已实现的范围

- ESP32-S3、16 MiB Flash、8 MiB PSRAM，使用未修改官方镜像及真实 S3 ROM。
- ST7789V 240×320 GRAM 中的固定 170×320 可见区域（列 35–204），保留现有 CAD 屏幕的 −90° 安装方向。
- 两条实际使用的 8 位并行路径：LCD_CAM i80 的 GPIO 矩阵路由和物理 D/C 电平；TFT-eSPI 的 GPIO WR 上升沿。D0–D7 为 39/40/41/42/45/46/47/48，WR8、DC7、CS6、RST5、RD9。
- USB 供电下的 RST、RD 与背光门控。制造商注明 GPIO15 为电池供电门控，不能把它当作 USB 供电的总开关。
- GPIO38 背光使用已生效的 LEDC 占空比或软件 GPIO 高电平。平均亮度是数字显示近似，没有校准实际背光芯片的 16 级脉冲协议或光学亮度。
- GPIO0 / GPIO14 低有效按钮，独立客体 `l32i` 指令验证单按、释放、组合及暂停后的释放。字体演示不处理按钮；这项测试不等同于出厂按钮处理程序验收。

错误的 WR、CS、DC、数据线、IO_MUX、输出使能和读写门控均不会产生有效写屏。LEDC 错误通道、关闭时钟、零占空比和重启均有边界测试；待生效占空比不会提前亮屏。

## 冷显示同步

`BoardModel::uses_gpio_pwm` 默认关闭。S3 仅在板型启用后，通过 `gpio_pwm_at` 查询现有 `Ledc::output` 的已锁存状态。`SocBus::refresh_board_outputs` 在现有网页画面发布和原生 PNG 捕获前调用；它只更新可见背光派生状态和画面版本，不推进外设时间，不新增 tick 轮询。显存导出仍显示原始 GRAM，不应用背光。

原生 `write_tft_png` 因需要更新派生状态改为 `&mut self`；现有调用方和 workspace Clippy 已检查。GPIO38 的反向输出使能路由不在当前支持范围。其他未启用板型不查询 PWM。

## 出厂固件的保留失败

出厂镜像 SHA-256：`f288081645eecf7bf6a17fd7b5bc2e724121d00cdc2099b5a5ea7db5107eb9fa`。

ROM 启动后能够发送 11 个 LCD i80 阶段并完成部分 ST7789 初始化，但没有像素。客体停在 `0x4206263c` 附近轮询 LCD `INT_ST` 的 `TRANS_DONE` 位。GDMA 描述符 `0x3fca7cc4` 为 `0x40001001`（1 字节、EOF、CPU owner），CHECK_OWNER 已启用，因而当前模型保留描述符错误，不伪造完成中断。

历史制造商源码 `0cc4b3a13f46855e954a81f1866c158afe57cbd8` 的额外 Sleep Out 命令传入非空参数指针、长度 0；IDF 4.4.4 根据指针启用数据阶段，而零长度不重新挂载 DMA 描述符。这解释了当前模拟器观察到的旧描述符重用。它**不能证明真实硬件或厂商固件有缺陷**；DMA/FIFO 的硬件行为差异仍需明确证据。未修改二进制、未跳过初始化、未关闭 owner 检查。

本次将范围收敛到已验证的字体演示显示子集，保留以上阻塞。接下来若修复 LCD/GDMA，应先取得具体硬件语义依据并增加能够区分旧、新行为的测试。
