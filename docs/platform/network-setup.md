# 连接你自己的网络助手

模拟器和固件运行在浏览器中。固件 SoftAP 配网页可直接在工作台内打开；要让固件访问真实网络，请自行部署网络助手，再把地址填入页面底部的“网络”面板。本站不提供默认公共中继，也不要求网站维护者为你部署服务。

| 方式 | 部署位置 | 工作台填写的地址 | 能访问什么 |
| --- | --- | --- | --- |
| 本地助手 | 当前电脑 | 终端输出的 `Pages connection endpoint`，通常为 `ws://127.0.0.1:8787/network?token=…` | 互联网、电脑和局域网服务；支持将固件服务映射到本机端口 |
| 云端助手 | 你自己的云服务器 | `https://你的域名` | 互联网；不支持局域网访问和入站端口映射 |

## 1. 自己部署本地助手，指向本机

当前电脑需要 Git、Node.js 和 Rust。首次运行：

```sh
git clone https://github.com/zhuzhe1983/esp-online-tester.git
cd esp-online-tester
cargo build --release -p esp-network-backend
node tools/network-helper.mjs
```

保持终端运行，然后打开终端输出的 `GitHub Pages workspace` 链接，它会自动连接这个助手。也可以在已有工作台的“网络”面板选择“本地助手”，粘贴 `Pages connection endpoint`，点击“连接”。地址必须包含助手生成的临时 token；不要把示例省略号当成实际凭据。

固件依然在浏览器运行，联网请求经当前电脑发出。访问局域网服务时使用该服务实际可访问的地址。终端关闭后，助手连接及本机端口映射也会关闭；重启后使用新输出的连接地址。

浏览器可能要求本地网络访问权限。如果浏览器不允许 HTTPS 工作台连接本地助手，可按[本地助手说明](network-helper.md)准备本机工作台所需的 WASM、ROM 并打开终端给出的本机 URL，或配置可信的 HTTPS/WSS。

## 2. 自己部署云端助手，指向公网地址

准备一台 Linux 云服务器、指向它的域名、Git 和 Docker Compose。服务器开放 TCP 80/443，并允许所需出站流量。在服务器上运行：

```sh
git clone https://github.com/zhuzhe1983/esp-online-tester.git
cd esp-online-tester
bash deploy/network-relay/start.sh relay.your-domain.tld
```

把 `relay.your-domain.tld` 换成自己的真实域名。脚本会构建服务并启动 Caddy，自动申请 HTTPS 证书。服务器已有网站占用 80/443 时，按[云端部署说明](public-network-relay.md)接入现有反向代理。

部署完成后，检查 `https://你的域名/health` 是否返回 `ok: true`。在工作台选择“云端助手”，填入 `https://你的域名` 并点击“连接”。这里填写的是服务基础地址，不是 `/health`、`/session` 或带 token 的 WebSocket 地址。其他开发者使用这个服务时只需填写该地址，无需在自己的电脑再安装助手。

云端模式在代码和 API 中仍叫 `public-relay`。它使用独立的出站服务入口，默认允许 TCP 80、443、1883、8883，以及 DNS、NTP；需要其他端口时按部署说明调整。它不能访问私有地址、你电脑的局域网，也不提供固件入站端口映射。费用、域名和服务维护由部署者负责。当前服务没有用户账号体系，允许来源和连接限额不等同于“仅本人可用”。

## 配网页和联网状态

未连接助手时，保持云端模式并关闭“自动配网”，仍可在工作台内操作固件的 SoftAP 原始配网页。`192.168.4.1` 等地址属于模拟器虚拟网络，不是可以直接在电脑浏览器地址栏访问的局域网设备。

连接助手后，“自动配网”会对已支持的固件流程提交虚拟路由器配置；其他固件仍可手动操作原网页。助手连接成功、固件取得地址、目标服务返回响应是三个不同阶段，实际联网结果以固件收到的响应为准。

连接地址与临时凭据只保留在当前会话，不写入场景分享链接或录制。页面重载后可重新填写地址，或重新打开本地助手输出的工作台链接。
