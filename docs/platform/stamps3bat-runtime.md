# Stamp-S3Bat runtime subset

S015 has an independent `stamps3bat` board with 8 MB Flash and 8 MB Octal PSRAM. Its single RGB LED is controlled by M5PM1 at I2C address 0x6e, routed through SDA48/SCL47. ESP G21 RMT output does not drive that LED. [Official product](https://docs.m5stack.com/en/core/Stamp-S3Bat), [official RGB example](https://docs.m5stack.com/en/arduino/m5stamp_s3bat/rgb_led).

S015-DIP remains a separate catalog product with its own model and fixed UIFlow entry. Its official page uses the same S3-PICO N8R8, M5PM1 routing and schematic; its supplied soldered 2.54 mm headers are a mechanical difference. It therefore uses the same electrical board implementation, with an independent full-ROM worker run and [DIP-specific receipt](evidence/stamps3bat-runtime/fixture-s015-dip.json). [Official DIP product](https://docs.m5stack.com/en/core/Stamp-S3Bat_DIP).

The model starts with PWR_CFG 0x07: the LED and external 5 V output are off. NeoPixel output requires PM1 GPIO0 configured as an output, push-pull, special function, LED_EN high and a valid LED count. RGB565 little-endian buffer writes at 0x60 are visible only after NEO_CFG 0x50 receives REFRESH bit6. Power loss discards the visible color; power restoration requires a fresh refresh. The digital command completes immediately. Full-range RGB565 expansion is a presentation convention, not measured optical brightness. Only the one physically mounted LED is exposed. [Pinned driver protocol](https://github.com/m5stack/M5PM1/blob/315d2899c863ae34b59197392b9f4c59490751ef/src/M5PM1.h).

`power` is a PM1 input, never an ESP GPIO. The supported control reads BTN_STATUS 0x48 bit0 and its read-clear flag bit7. New presses are accepted only after guest firmware sets BTN_CFG_1 bit0 and BTN_CFG_2 bit0 to disable automatic single-click reset and double-click shutdown; release remains accepted. Autonomous reset, shutdown, download entry, click/IRQ timing and wake are not implemented. The UI therefore calls it “PWR（状态读取）”. I2C shutdown requests affect the modeled LED rail but do not stop the CPU. No physical power-off animation or compatibility claim is made.

The inherited PM1 ID/model bytes are 0x50/0x20; hardware/software revision bytes 0x05/0x06 are the existing virtual PM1 profile, not an identification of every shipped S015. Battery voltage is an explicit virtual 3900 mV default. Analog rails, charging, USB power transitions, external connectors and networking remain outside this subset.

Factory investigation checked the exact S015 product/tutorial sources, M5PM1 repository and official M5Burner metadata. No fixed, source-proven factory recovery image was located. The official RGB tutorial is an example, not factory firmware. The catalog therefore retains the exact UIFlow2 alternative first: project `1897200000000003091`, device category `1897100000000000016`, version `2116031366191419394` / v2.5.4. Its project explicitly covers Stamp-S3Bat and DIP. The fixed download requires M5Burner verification (`BURN_CAPTCHA_INVALID`, historical catalog receipt 2026-11-03); no challenge was bypassed and no unavailable image is claimed tested. The entry remains `trial`, `simulationVerified:false`. No exact Xiaozhi target was located in the audited upstream tree. [Official UIFlow project](https://burner.m5stack.com/firmware/1897200000000003091), [UIFlow source target](https://github.com/m5stack/uiflow-micropython/tree/f20d5a00e8c9106aae1d944f3d6f1128839f59cb/m5stack/boards/M5STACK_StampS3Bat).

`tools/fixtures/stamps3bat-firmware` and `tools/probe-stamps3bat.mjs` provide a separate real-worker protocol test. Its receipt is evidence for that source-built diagnostic only. It does not establish official UIFlow or factory compatibility and is never added as a public default firmware.

The S015 internal-fixture worker probe passed all seven staged LED/power observations, four fresh press/release cycles including the read-clear flag, wrong-address/wrong-pin checks, real 8 MB Octal PSRAM initialization/memory test, pause and platform reset. See [the retained receipt](evidence/stamps3bat-runtime/fixture-s015.json). Three focused board tests and twelve shared PM1/M5IOE1 regressions passed; native Clippy denied warnings. Platform catalog schemas and config/runtime/input tests passed. Product model and human browser interaction are audited separately.
