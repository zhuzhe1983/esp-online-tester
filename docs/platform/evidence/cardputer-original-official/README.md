# Original Cardputer official v1.1 evidence

`cardputer` implements the K132/K132-V11 shared, source-confirmed baseboard path: original 74HC138 GPIO keyboard and ST7789V2 LCD. It does not select the Adv TCA8418 model. The remote M5Burner image boots from the ESP32-S3 ROM with JIT enabled; no app-direct path, firmware patch or substitute screenshot is used. No physical hardware was connected/flashed.

- `source.json`, `m5burner-entry.json`, `sources.json`: actual source fetch timestamps, hashes and published metadata. K132 and V1.1 schematic URLs are separate official links with identical content hash. The internal app says IDF 4.4.6 / f0b37ae-dirty, so neither the public base revision nor current main is claimed as an exact rebuild source.
- `k132-interaction.json` and the V1.1 receipt retain actual matrix inputs and guest acknowledgments, complete frame hashes, counts and times. Screenshots contain public official firmware output. The stable selected menu is RECORD, right selects CHAT and left returns to RECORD.
- `negative-results.json` retains the rejected missing-IR-load run, pixel equality failure and host timeout. Before the IR load, actual M5GFX identified VAMeter; the screen crop was wrong. The correction is a sourced GPIO load, not a framebuffer offset workaround.
- In the menu comparison, the 160×75 interior is byte-identical after at most 2 px integer horizontal translation. Raw full-frame hashes differ and remain recorded. No pixel color tolerance or synthetic OCR claim is used. This source uses easing; exact physical display timing has not been calibrated.
- `checks.json` lists final test commands/artifact hashes. Native performance is measured separately against the existing main baseline; it is not inferred from host elapsed time of this correctness probe.

The new `uses_gpio_routes()` opt-in reuses the existing route callback after GPIO/IO_MUX writes and attachment. Original Cardputer needs combinational row selection, not pulse decoding, so `uses_gpio_waveform()` remains false; other waveform boards retain their previous default behavior. This does not alter CPU/JIT clocks or add per-tick peripheral work. Historical mechanisms: EX217 (GPIO feedback), EX218 (routed waveform callback); this is a board correctness extension, not a speed experiment. Open upstream PRs were checked before extending the board interface; none touched the two modified shared interface/bus files in that query.

The 74HC138 model releases unpressed switches so MCU pulls remain meaningful. A pressed switch connects to selected LOW or other HIGH output. Opposing multi-key outputs use LOW dominance, with no claim about analog contention, ghosting or contact bounce. GPIO44 only represents the IR diode input detection load, released in GPIO output mode; optical emission is unimplemented. The firmware battery ADC reads 0. SD/audio/wireless/HID, power switch and all menu applications are outside the verified scope.

Reproduction commands are in [runtime scope](../../cardputer-runtime.md). Third-party firmware bytes are fetched into RAM only for these probes and are not retained here; browser firmware caches are separate user-local storage. Only curated public firmware console lines are included; private device data and local account paths are omitted, with no change to measured values or artifact hashes.
