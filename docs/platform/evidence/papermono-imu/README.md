# PaperMono / Lite BMI270 客体采样时钟

本次沿用共享 BMI270 数字模型，在 `papermono` 与 `papermono-lite` 板级启用客体微秒时钟与期限调度，并接入明确的虚拟传感器轴。没有改变官方固件、默认固件选择、CPU 时钟或通用调度器。

## 原因与负面基线

基线 `7f0498df` 的生产 WASM 为 `0d5dc1d9cd45e2bc4648c5f52d09876b3f7ec2d7fb3f7224f5ecba74ffa9d0a1`。固定官方 UserDemo 1.2.0 的完整镜像 SHA-256 为 `72c290bc2ffa216041b276660277369bd17ecef92315e367d98bb2c96c8428fa`，实际从 ROM 启动，固件报告 IDF 5.5.1。

完整版与 Lite 均正确识别 BMI270，随后三次出现 `detected=1 mask=0x00`，最终 `IMU init failed`。官方 HAL 在 500 ms 内要求加速度和陀螺仪数据就绪；旧板型只按外部样本版本变化产生就绪，初始化过程中读取过一次后不再出现周期事件。仪表盘的默认向量不代表此初始化验收通过。[负面回执](baseline.json)保留两台板型的实际结果与相关 HAL 信息。

`b4b815f7` 将同一 BMI270 实例同时交给板级时钟和软件/两个硬件 I²C 控制器；其配置覆盖检查、ODR、power-control、读清和数据缩放仍由共享器件执行。宿主姿态输入先结束当前客体时刻的旧样本，再等待下一传感器采样点，不直接改就绪标志。`65a3b151` 添加官方 IMU 专属探针。共享平台映射由 `352973c7`（此分支 `653fe8fa`）提供。

## 实际结果

候选生产 WASM `054cdbdee135e264200f12c81e22f0f863d2307a3058ad1e7efc09924549b988` 在完整版和 Lite 上均报告 `IMU ready type=6 attempt=1`，没有后续重试或初始化失败。参考区域 hash 为 `a687ffec…879fb8a`；输入倾转和角速度后为 `56a31916…20729a5`，截图实际显示 AX 1.0、AY 0.0、AZ 0.0、GX 10.0、GY -20.0、GZ 30.0；恢复后区域和整幅图均回到参考 hash。输入参数、客体时间、完整 hash 和执行计数见 [官方 WASM 回执](official-wasm.json)。

## 验证方法

官方 AppImu 平时每 30 秒刷新显示，触摸 `(75..220,543..632)` 可要求一次刷新。探针等待真实客体时间，再依次输入单位姿态、绕 Z 轴 90 度且角速度 `[10,-20,30]`、恢复单位姿态，每次触摸 `(100,580)`。只比较 `(75,543,145,89)` 的真实 framebuffer 字形区域，避免时钟、无线区或其他刷新造成假阳性；继续人工检查实际数值截图。HAL 首次初始化成功、像素变化和恢复均要求通过，输入回执本身不算成功。

```sh
ESP32SIM_PROBE_CLOCK_TIMEOUT_MS=60000 node tools/probe-official-papermono.mjs \
  https://m5burner-cdn.m5stack.com/firmware/376080df0d31b0026e9a67a75d02d571.bin \
  72c290bc2ffa216041b276660277369bd17ecef92315e367d98bb2c96c8428fa \
  output/papermono-imu-full 15 imu m5stack-papermono
# 同一命令最后两个参数改为：15 imu m5stack-c153-lite
```

板级回归覆盖两个型号：完整 8 KiB 配置前禁止采样、100 Hz 的周期数据就绪、两个 I²C 控制器共享读清状态、加速度/陀螺仪缩放、非法输入拒绝、关闭传感器和复位。传感器完整寄存器测试和模型限制见 [BMI270](../../../bmi270.md)。

## 基础功能回归

同一候选 WASM 顺序运行完整版和 Lite 的 `controls`、`sd-rgb`，四次均通过。A/B 改变并恢复亮度文字，触摸加号和静音图标变化及恢复；RGB 实际输出依次为红、全关、绿、青。官方 TF 浏览器读取生成的 FAT32 目录，显示 `HELLO.TXT / 17B`；重新建立运行实例后再次打开目录，整幅实际 framebuffer 两次均为固定 `c229c0df…e53d9`。这验证客体真实目录读取和媒体恢复，不把主机导出文件当客体读卡，也不宣称官方固件写文件。

[基础回归回执](core-regression.json)保留四次运行结果。将上方命令的 `imu` 换为 `controls` 或 `sd-rgb` 可复现。板级 6 项与平台 IMU 14 项定向测试已由集成构建通过；完整 CI 和浏览器验证由集成记录提供，本文不扩展其结论。

## 范围

虚拟轴是明确约定，不代表真实 PCB 安装方向。平台 `sampleTiming: host-input` 仍描述姿态输入到达时间；BMI270 寄存器中的新数据与就绪事件则按客体时钟、固件 ODR 产生。场景旋转联动默认关闭。

本次不接入 BMI270 INT1 → PM1 GPIO4，不证明 IMU 唤醒、深睡、独立供电轨、FIFO、模拟噪声或实机安装方向；原有 RTC RAM、前光光学与其他未验收功能限制保留。没有进行硬件或光学校准，也没有修改共享 BMI270 器件或伪造灰阶。

来源下载信息见 [sources.json](sources.json)。原始固件仅留在进程内存；回执省略完整串口中的网络标识、无关设备日志与宿主信息。原始与整理后回执分别保留 hash。截图和原始输出留在忽略的 `output/` 目录，Git 只记录必要的数值、hash、命令与结论。
