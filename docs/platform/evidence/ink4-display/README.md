# INK4 连续局刷旧画面修正

2026-11-12。固定官方 2.0.53 的实际 SPI 序列为：开机向 `0x26`、`0x24` 各写 48,000 字节后 `0x22=C7`；随后仅向 `0x24` 写整帧，再以 `CF` 局刷。模型只翻转了 Mode 2 face 标记，没有交换 RAM，所以 `0x26` 始终停在开机画面。结果是旧标题残留，按 Home 后还会保留整页设置内容。修复在 BUSY 完成后交换两块 RAM 的所有权，让上一幅实际刷新图成为下一次的旧图；没有在主机绘制文字或强制替换页面。

[SSD1677 rev1.0](sources.json) 第 32 页规定 `0x37` 第六字节 F[6] 控制 Mode 2 RAM ping-pong。现在也接受该显式开关。2.0.53 实际未写 `0x37`；较新公开源码 d12f481f 才显式写 `0x40`。默认开启延续现有模型的 Mode 2 face 契约，与支持的驱动行为相符，**不代表已读取或实测面板 OTP**。M5GFX 重写双 RAM 的四灰阶映射及切回 Mode 1 的 face 处理保留，EDC Book 的 C4 分段驱动也保留。

真实 WASM 前后截图已逐张检查。设置页正文逐像素相同，差异全部在顶部 44 行：335 个旧黑像素擦白、27 个像素变黑，标题成为单一、清晰的“配网模式”。这个标题由原固件在配网状态设置，没有强行改成“设置”。Home 返回后恢复时钟和六个应用图标；旧模型此前仍显示设置页。原先“hash 变化”验收不足，专属探针现增加主页主体像素相等断言，防止再次把标题变化当成成功返回主页。

两项新增单测覆盖连续只写当前 RAM 的局刷、BUSY 边界、显式禁用 ping-pong、Mode 1 和复位。9 项 SSD1677 测试及定向 Clippy 通过；删除 RAM 交换后，新增连续刷新测试失败。前后 WASM/固件/ROM hash、SPI 事务计数、图片 hash、数值比较与限制见 [receipt.json](receipt.json)。图片、原始串口和运行标识不提交。

复现沿用 `tools/probe-official-ink4.mjs` 的固定远程官方 URL/hash；`docs/platform/ink4-runtime.md` 提供命令。这个修复校正数字 RAM 与刷新结果，未校准真实墨水颗粒、温度、波形灰阶和光学残影。
