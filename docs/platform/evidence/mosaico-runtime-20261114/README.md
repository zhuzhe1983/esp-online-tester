# Mosaico browser acceptance, 2026-11-14

The exact official recovery image, SHA-256 `7562ff67cad8280fe8fdd06f3be7d6c91f44e5a8cc63fe596721f48da428af9b`, boots unmodified through the production S31 WASM worker. [Receipt](receipt.json) names checks, negative observations and hashes. [Worker receipt](worker-receipt.json) includes the command inputs, four framebuffer hashes and guest output. This is functional acceptance, not a CPU benchmark or silicon qualification.

The workbench accepted real 2D pointer input, a 3D screen touch at guest `(40,40)`, and keyboard A standby/wake; see [workbench receipt](workbench-receipt.json). The retained acknowledged 2D touch results in the Chinese multifunction page and the 3D back touch returns home. An earlier frame capture still showed language selection and is not used as touch-response evidence. `workbench-home-3d.png` and `workbench-keyboard-standby.png` show the resulting guest display. These captures precede the final rear-label/inspection-only model refinement.

The configuration-only share (`autostart=0`) restored the product, key mapping and exact remote URL/hash in the mini player. The actual publisher fetch failed CORS. The existing recovery dialog exposed the original download address, local BIN selection and SHA-256 check (`mini-download-recovery.png`); selecting the original file let the same mini scene boot. Its source receipt remains “remote” because cache recovery deliberately retains the pinned source identity. **That label is not proof of direct remote downloading.** A new recipient still needs access to the file. Local bytes are not in the shared URL; the workbench API correctly refused sharing a local-file execution with `LOCAL_FIRMWARE_NOT_SHAREABLE`.

The mini then accepted 3D touch to choose Chinese and onscreen AI-button standby/wake with corresponding serial output. [Mini receipt](mini-receipt.json) retains acknowledged inputs and the recovery provenance. Its first AI presses on the language-selection page had no observed application action; successful standby/wake was checked after onboarding. The new mini runtime returned to language selection without a storage clear, so cross-runtime language persistence is **not accepted**. The volatile NAND and existing scoped Flash are distinct.

After the final model refinement, the same source was loaded from the explicitly imported browser cache; [final render receipt](final-model-browser.json) records the exact final model, geometry and production WASM hashes. `mini-home-2d.png` and `mini-home-3d.png` show the same actual guest framebuffer on both surfaces. They do not use a printed screenshot as the model screen texture.

The browser ran headlessly through the Playwright wrapper. Its task-owned session was closed and absent from the subsequent session list; the local preview listener was also stopped. Only expected publisher CORS failures appeared in the browser console; no firmware or model-loading error was observed. Model geometry, sources, dimensions and photo deviations have a [separate receipt](../mosaico-model/receipt.json). Third-party binaries and original photos are not committed.

Reproduce the worker acceptance with `node tools/probe-mosaico-factory.mjs OFFICIAL_BIN OUTPUT_DIRECTORY` after `tools/wasm-build.sh` and the pinned ROM fetch. To repeat the UI checks, use a task-owned browser session: select ESP-Mosaico V1.2, select the original local BIN, load and start, choose Chinese on the real display, and verify AI standby/wake against the serial log. Create a configuration-only share with the pinned official source, open the mini, and exercise the actual download-recovery prompt; do not substitute a test server response for the publisher's CORS result.
