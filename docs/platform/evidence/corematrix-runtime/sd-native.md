# CoreMatrix original-firmware SPI SD read/write

The official UIFlow 2.5.4 binary identified in [c61-native.md](c61-native.md)
mounted a dedicated FAT32 card through `machine.SDCard(slot=2)` and the real
C61 SPI/DMA path. `cm_sd()` from
`tools/fixtures/corematrix-uiflow/exercise.py` wrote
`COREMATRIX_SD_PERSISTENCE_1\n` to `/sd/corematrix-fixture.txt`, called
`os.sync()`, opened the file again and asserted exact equality. The guest
printed `CM_SD WRITE_READ`, then returned to the original MicroPython REPL.

The board observed 47 card commands, eight read blocks and six written blocks.
The trace used SCK25/MOSI27/MISO26/CS28; CS was released during startup clocks.
The native run completed its 1,158,000,000 instruction budget with final stop
`MaxInsns`. The harness set `stop_after_exceptions=1`, but this capture did not
print the accumulated exception count; it is not a direct zero-counter receipt.
The blank input card was 67,108,864 bytes, generated by the platform's
`createFat32Image`; SHA-256
`a0e026d9aeafab624884455d25147647980bd6a83011618da04140659c28bfc6`.

Reproduce with caller-supplied ROM/firmware paths and a task-owned disposable
card. Create `$GUEST_SCRIPT` from the fixture followed by a blank line,
`print("SD_BEGIN")`, `cm_sd()` and `print("SD_END")`, each with a final newline.
The executed script was 3448 bytes, SHA-256
`b33e8f27fdb11d34dbf7fc9c6cdf6e6544ed36f0362173e13f7bddeb0513c1b1`.
The native
example receives the input card into memory and never substitutes host file I/O
for the guest's SPI transactions.

```sh
cargo run --release -p esp32c61 --example firmware -- \
  "$ROM_DIR/esp32c61_rev100_rom.elf" "$COREMATRIX_BIN" \
  100000000 "$GUEST_SCRIPT" "$TEST_SD_IMAGE" 1000000000
```

Before C61 fix `6e9fca40`, the guest stalled in SPI `TRANS_DONE` polling at
PC `0x4216de86` and the card received zero commands. ESP-IDF v5.5.4's C61
AHB_GDMA v2 uses SPI2 peripheral selector 1, low-bit link commands, separate
full-width descriptor addresses, and RX DMA scattering. Applying those
C61-specific rules made the same original firmware exercise pass; the physical
board pin and card protocol model did not need a compensating change.

This receipt establishes native guest filesystem write/read through SPI.
Platform restart persistence, browser audio and browser runtime evidence are
separate checks. It does not claim SD electrical signal integrity or timing.
Only public input hashes and curated protocol counts are retained here;
machine-specific paths and verbose traces are omitted.
