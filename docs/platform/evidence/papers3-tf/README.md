# PaperS3 SPI TF support

The C139 socket is SPI (SCK39, MOSI38, MISO40, CS47), while the prior platform only attached SD through native SDMMC and only exposed TF storage for PaperMono/Lite. An unmodified caller-owned full image consequently failed CMD0. The new SPI endpoint reuses the existing SDHC card/store, including CSD/CID capacity, data blocks and erase; it does not replace the guest's filesystem implementation.

`[SD] SD card detected` appears in both native and actual browser-worker execution. The guest writes a 2,389-byte file spanning five FAT32 clusters. File SHA-256 `bc717c1439f4f44cd1635643e6438402104c5b7545a0003e80d9b0f5914e8784` survives reset and fresh-worker reload. IndexedDB page reload and mini reuse exactly the same 64 MiB image (`7efb023f7b0ed9d22777a71b6873cd40c9b2fb35554f1ee489098f40eff47255`). The private image is 6,406,048 bytes, SHA-256 `0d84eda76334b4fe6e26bcad4760e44d1dc736d891b8427cb061b8e1734e9a60`; it was neither modified nor committed. The actual native 20-second run read 37 blocks and wrote 22. These observations validate this SD workload, not the full application.

The workbench and mini expose existing TF controls under **设备存储**. Explicit clear and import preserve Flash, leave ready, and never run automatically. Product, board and initial full-Flash SHA remain in the storage key. Wrong pins/CS/MISO and no card reject communication; command/data CRC, multi-block read/write/stop and CS cancellation have bounded unit tests. Existing recording checks still reject imported/modified SD so private files are not encoded in URLs. Card power follows the schematic's SOC_VDD; no fabricated GPIO gate was added.

## Reproduction and evidence

- [Sources](sources.json): actual GET URL, final URL, UTC timestamp, media type, byte count and SHA. Official C139 V1.0 schematic **J3** and docs; independent host driver is SdFat **2.3.1**. Existing native SDHC card is based on SD Physical Layer Simplified v9.10; this addition covers chapter 7 framing only within the stated subset.
- [Original-image worker result](private-firmware-result.json), using `node tools/probe-papers3-sd.mjs --file <caller-owned-complete-PaperS3-image>`. The harness reads the supplied file in RAM and never uploads it. It deliberately records only hashes/counts, not full serial or private filenames/content. Its expected SD log/file assertions describe this tested workload; other firmware may log or create files differently.
- [Browser checks](browser.json): actual local upload, IndexedDB reload, visible confirmation control, import, non-pristine recording refusal and mini mount. The original screenshots and raw test logs remain ignored locally because they contain private UI/serial data.
- [Checks](checks.json): 1,565 Rust tests, both required Clippy passes, all 28 CI groups including real WASM/recording and JIT, 106 platform tests; no golden regeneration. Final added cancellation assertions and board routing tests plus all-target Clippy were rerun after the full pass.
- [CPU](cpu.json), [harness](compare-cpu.py): separately built fixed `61e1808f` baseline and candidate, five alternating 30-guest-second pairs for S3/C3/C6 hello, identical UART hashes and instruction counts. Median user deltas −4.00%, −0.84%, −1.86%; short S3 runs are quantized to hundredths of a second. This is a regression guard, not an optimization claim. No browser/guest/build competition during timing. The core, per-tick work and SPI host implementation were unchanged; Pocket was not rerun.

## Limits and retained failures

Only SPI **SDHC immediate digital** behavior is implemented. No SDSC, analog/radio behavior, calibrated startup/program busy timing, arbitrary half-duplex driver semantics, physical hotplug or complete SD compliance is claimed. Native SDMMC and its existing tests remain separate. The default virtual card uses a small FAT32 disk image accepted by the tested SdFat host; importing other formats does not certify they can mount. RTC, audio, power control and network/display limitations of PaperS3 remain unchanged.

Baseline CMD0 failure and subsequent test-harness failures are retained in `checks.json`; raw private logs stay outside Git. The new cold `BoardModel::attach_spi_sd_card` method is appended, so integration must retain other lanes' appended cold accessory methods. Rebuild production WASM after merging the source union; this branch's WASM is not a replacement for newer product changes on main.
