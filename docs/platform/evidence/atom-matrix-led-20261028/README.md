# Atom-Matrix 低 PWM 显示

官方原版 Atom-Matrix 固件在 0.4 guest 秒输出首灯 `[5,0,0]`。修复前后真实 worker 返回的全部 25 颗 RGB 值一致；只改变材质显示，未调整固件、PWM 或模型。`official-5.png` 是实际固件的三维页面截图。

问题来自显示响应：线性 5/255 的发光面太暗，均匀方形材质仍像涂色塑料。原版/v1.1 的 LED 面 z≈6.96，在黑色窗口 z≈6.92/6.905 之前；更近的 `cover-key` 仅为 opacity=0、depthWrite=false 的输入代理。没有改变盖板透明度。

现在使用 `0.62 × (peak/255)^0.20` 的有界显示响应，按同一倍率缩放三通道以保留色相与顺序；原始 RGB 独立保留。灰度径向发光核形成柔和亮心，扩散仍做深度测试且不参与点击。零值恢复原来的未点亮材质，满值保留显示余量。这是可视化曝光，不是物理亮度标定。

`before/after-original.png` 与 `before/after-v11.png` 均为**合成显示校准，不是固件验证**。列为 0/1/5/19/255，行为红、绿、蓝、混合色、白；使用实际厂家 CAD、相同正视相机和光照。两个版次的红色中心读数一致：

| PWM | 修复前红通道 | 修复后红通道 |
| --- | ---: | ---: |
| 1 | 52 | 143 |
| 5 | 77 | 164 |
| 19 | 129 | 184 |
| 255 | 255 | 231 |

关闭时像素 `[45,48,48]` 前后完全一致；满白中心从 `[255,255,255]` 变为 `[231,231,231]`。完整原始 RGB、线性材质值、像素值与来源/资产 hash 见 `receipt.json`。像素数字只对应记录的浏览器渲染条件，不代表任意显示器或实物光通量。

验证：106 项平台测试通过，包括 RGB 数据不变、色相比例、全部 PWM 单调性、零值、光晕上界及点击隔离。真实官方 BIN 使用 SHA-256 `24892fcf5d5f8c97ee30a5ffb4fec166dca1c254cc6f54861af28abc8732ba2f`（2,166,576 字节），仅放本地测试目录，未发布二进制。没有修改 Rust/WASM。自有浏览器和服务均已关闭。

复现：先用 Playwright wrapper 打开调用方指定的平台 URL，再运行 `run-code --filename tools/browser-rgb-led-calibration.cjs`（先创建 `output/playwright`）；脚本导出两台模型的合成校准截图并检查低值可见性、顺序和满值余量。真实固件验证则选择原版 Atom-Matrix，通过本地文件载入上述原始镜像，在首个 `[5,0,0]` 输出后暂停；不要用合成 RGB 调色取代这一步。
