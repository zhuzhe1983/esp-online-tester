# StampFly UART demonstration evidence

The final public image is `b5f9665ed7a879396c75171c02e699e4e02f0b0686f942721c1cedebde74381b` (349328 bytes), from source commit `58824a076758cada02325d58ed7477e2f7a7e065`. It is an independently authored UART demonstration, not M5Stack factory firmware. The original and v1.1 factory selections remain the defaults. No physical flight or calibrated aircraft behavior is claimed.

- `rebuild-final.json`: bootloader, partition table, application and merged image are byte-identical across two private ESP-IDF5.5.1 build directories. Source files match the reachable integration commit. One toolchain/host was used.
- `manifest-final.json`: actual normal-ROM worker boot through both exact public manifests; fresh UART commands produce four independent FL5/FR42/RL10/RR41 LEDC outputs and G21 RMT status changes. Invalid commands preserve output, pause freezes execution, STOP and reset produce exact zero PWM. This run uses the final image and WASM `4d8d85eb406e4c3641e5166ac1318d5d7b3ec5f4b7e5230ed5c8c406e7f762d6`.
- `flight-final.json`: two-SKU takeoff/hover, altitude change, combined roll/pitch/yaw target, return to level and landing; separate original-SKU 0.10/1.50m boundary samples; explicit ToF target-loss test. Each entry links its complete compressed input/output trace and hash. Normal flight uses unchanged production worker/plant assets.
- `control-negative-01.json` and its complete compressed trace retain the first controller's failed combined-axis qualification on prior image `dba1e1b0…`: large angular oscillations and failure to land within the requested interval. The final controller uses coupled FRD Euler integration, applies accelerometer gravity correction only in STOP, and uses lower attitude gains. The original ST ranging algorithm and its history remain unchanged.

The normal sequence's settled altitude errors are at most 4.1cm over the specified final four-second windows; the sampled 1.50m boundary reaches 5.0cm. Combined-command final-one-second roll/pitch errors are below0.9° and yaw-rate errors below1.5°/s on both SKUs. Return-to-level errors are below0.9° and yaw-rate error below0.5°/s. Each normal flight ends with contact, guest STOP and four exact zero duties. These are bounded scenario checks, not a guarantee over every simultaneous input extreme.

The ToF fault case removes only the bottom target after10s using a recorded test-only ESM transform. The real ST driver reports status255/no objects; by the published10.521s sample the guest has stopped and all four PWM outputs are zero. IMU remains valid. The plant then falls to the floor under its own dynamics. Production files and APIs do not contain the fault control; source hashes and the exact replacement are retained. IMU-stale handling is covered by the C controller test only, not by an injected guest failure claim.

`motor-worker.json`, `manifest-worker.json` and `rebuild.json` are historical motor-path evidence for the earlier image and are not relabeled as final-image tests. Browser/iframe rendering evidence is maintained separately by the platform integration task. All receipts omit private build paths; numeric samples, source revisions, hashes, commands and failure results are retained. Compressed JSON was decoded and manually checked for private paths/network addresses in addition to the repository privacy checker.

Reproduction commands and protocol limits are in [`firmware/stampfly-uart-demo/README.md`](../../../../firmware/stampfly-uart-demo/README.md). The public source receipt accompanies the image under `web/wasm/fw/public/`.
