# 四款旧相机/模块与 K024 分类纠错

这一批处理五个 SKU：新增四款主控预览，以及纠正一款教学配件的误分类。

| SKU | 已确认身份与模型范围 | 保留的边界 |
| --- | --- | --- |
| U007 | 原始 ESP32 Camera，4MB Flash、OV2640；采用自身正视/斜视和带尺照片建立长条 PCB、镜头、排线及接口近似 | 官方 54×54×26.6mm 规格与照片不符，模型约 50×23mm 为照片估算，误差数毫米级；不拉成方形，不沿用 U017 的 PSRAM或广角配置 |
| U082 | 普通裸板 TimerCamera，4MB+8MB、OV3660 66.5°，预留电池接口；PCB照片避开镜头、排线、夹座、Micro-B与安装孔 | 不继承 X/F 外壳、随附电池或 FishEye 固件；背面元件高度和整体 12mm 厚度尚未完整还原 |
| U109-X | UnitCAM DIY，ESP32-WROOM-32E+4MB，65°/160°两颗 OV2640；当前预览普通 65°装配 | 普通 40×24×11mm 与鱼眼 40×24×17.2mm 分开；采用自身壳体照片，不复制 U109 裸板尺寸。后部金属屏蔽罩、纸贴和针孔分别处理 |
| U133 | 旧版 Kmeter 内部为 ESP32-C3，MAX31855/I²C@0x66；原厂背贴直接证实芯片身份 | 不混入 U133-V11 的 STM32F030、隔离电路或固件；未确定 Flash/PSRAM，保持未知 |
| K024 | DHT12 教学扩展板，需要外部 M5Stack Core；官方 supplied-items 不含 Core | 不编造 ESP32、Flash、板型或出厂固件；本批交付分类纠错和独立配件知识记录，不新增控制器 |

四款预览都保持 `runtime.status: unavailable`，没有把相机外观、串口回执、主机示例或第三方画面当作设备模拟。相机 DVP 捕获、图传、温度转换、传感器校准、物理供电和固件运行都没有在本批实现。官方型号文档、原理图、出厂/内部程序与 UIFlow 链接已逐款调查；M5Burner 的 TimerCam 类目检索不能证明普通 U082、X、F 或 UnitCAM 的精确镜像匹配，故只加入来源参考项和不自动映射二进制的源码 watchlist。没有下载或镜像第三方固件。

照片材质保留原始来源、SHA-256、裁切和遮罩。裸板照片中已建模的镜头、排线、接口和孔洞从 PCB 照片层剔除，PCB 背面保留 `UNKNOWN`。U109-X 背面实际的 WROOM 金属罩使用独立金属体和照片面；只有真正纸贴才使用纸贴遮罩，外壳改色不会把金属和印刷一起染色。可见件的隐藏尺寸仍为近似，不能声称完整 PCB、装配精度或同视角照片验收通过。

`tools/build-m5-legacy-camera-models.py --output /tmp/m5-legacy-rebuild` 从保留且 hash 匹配的照片/原理图与显式计划离线重建，不联网、不生成参考照片。模型的源变换、近似尺寸、纸贴边界和支持面均保留。测试 `tools/platform-m5-legacy-camera-test.mjs` 实际加载四款，检查资产哈希、UNKNOWN、材质隔离、展开复位及两项身份边界；这不替代浏览器或实机测试。

K024 的正式独立配件知识记录位于 `research/m5-k024-accessory-knowledge-20261126.json`，按知识 schema 单独验证，暂不进入运行目录：连接器和电压契约尚无足够证据。图片中的 M5 Core 是需要另配的主机示意，不能从图中推导套件自带处理器。完整商店清单由 `confirmed-esp32-device: 44` 改为 `43`，增加 `requires-external-host-accessory: 1`；缺失确认主控 SKU 从 45 改为 44，总商店条目仍为 687。

本批未执行浏览器三种材质、完整照片叠图、官方固件启动或实机验收。最终 hash 与检查结果见 `evidence/m5-legacy-camera-audit-20261126/`。
