**September 23 x8 round:** fluidbox runs faster than real time in Chrome 153 on the M3 Pro. The shipped stack `x8/ship` `9e8d3378` (artifact `38e599d0`) has seven code slices, a TIMG timer fix and a per-target scheduling quantum. Against base8 (`codex/x7-closeout` `85c639db`, artifact `c2144b73`), both at the new 256-instruction browser quantum, 4 pairs each, every pair faster, it measured: fluidbox 24.243→19.787 s (**18.38% less**, 1.52× real time), Pocket Tank 17.700→15.501 s (**12.42%**) and TinyDraw 21.302→20.144 s (**5.43%**); the q256 fluidbox A/A measured −0.67% (2 pairs). Against base8 at its old 64-instruction default, which is different guest work (three alternating single arms each), x8/ship at q256 measured fluidbox 35.491→19.657 s (**−44.6%**, 0.85×→1.53× real time), Pocket 22.527→15.493 s (−31.2%) and TinyDraw 24.390→20.126 s (−17.5%). The code slices are the resume memo and memo hits from the round batch ([EX195](#ex195)), round batches that continue across device-register deferrals ([EX177](#ex177)), exits that name their decoded resume ([EX172](#ex172)), the `run_inner`, next-timer, no-region-verdict and mask-ROM-epoch diets ([EX168](#ex168)), region entry inside the region's own hardware loop ([EX196](#ex196)), store-run loops retired in bulk ([EX197](#ex197)), closed leaf callees inlined with static window renaming ([EX164](#ex164)) and register-quad window addressing ([EX198](#ex198)). Device events and cross-core hand-offs land up to 255 cycles late (63 before), and the pinned totals are new. Native keeps 64 and its golden pins, because native Pocket ran 5.38% slower at 256. Its review found a pre-existing TIMG autoreload defect, now fixed, and the follow-up review found it ready to merge. Native CLI screens of x8/ship are 2.75–4.64% faster than base8 with equal work. Different baselines: do not add the stage screens. Not adopted: short-credit copy dispatch ([EX182](#ex182) tailcut-s1), dirty spills at budget exits ([EX163](#ex163)), multi-chunk region loops ([EX181](#ex181)), leaf resumes (EX164 leaf-s3) and the code watch. Wave 4 retried exact mechanisms under q256 until the user stopped the round: the stack-window proof ([EX188](#ex188)) measured +2.24% on fluidbox; nothing from it was adopted. No M1 timing: the laptop carried unrelated heavy load. [x8 receipts and limits](evidence/perf-x8-2026-09-23/README.md).

**Reading the outcomes:** Worked means the stated bounded test succeeded; adoption is a separate column. Promising means favorable but insufficient confirmation. No gain means the stated test showed no useful improvement; that outcome applies to its workload and conditions. Invalid means the method cannot support its claim. Not tried, unbuilt and captured-but-unpriced are different states. “Not tried” means no completed result was found in the indexed sources. A plan's proposed priority expresses its recommended order of work; measured benefit comes from the experiment receipts.

FP means floating-point arithmetic. PIE is the ESP32-S3 vector instruction extension. A readiness scoreboard tracks when a prior instruction's result can be consumed. Host time is elapsed time on the computer; guest time is the emulator's modeled clock. A “price” is the cycle cost assigned to an operation. A differential test compares two execution implementations; matching them does not independently establish hardware truth. CUT is an early compiled-block exit/resume boundary.

## Internal call-edge constraints (EX164)

Design only; no measured adoption. The earlier direct-call ceiling was about 1.73 seconds of a 42.59-second TinyDraw battery (4.1%), assuming removal of every direct-call dispatch; eligible CALL8 sites are only a subset. The underlying exit census counted 45.6M direct calls, 8.2M indirect calls and 51.7M RETW exits. See [measurements](evidence/overnight-2026-09-19/measurements-1.md).

A direct CALL8-to-ENTRY edge must materialize caller arguments and stack state, preserve pre-call overflow behavior, reload the callee window after ENTRY and retain the post-ENTRY collision guard. Budget cuts and CCOMPARE delivery must remain exact. Callee pages need version validation; writes, probes and stubs must still force the appropriate exit. A return edge must validate the computed return PC and renew window-collision checks. Unsupported calls and returns retain existing exits. Required tests include nested calls, recursion, cuts around ENTRY, window overflow/underflow, timer delivery and self-modifying callee code. These are acceptance constraints, not a claim of an implemented or validated edge.

## Keeping this list authoritative

Before proposing, implementing or benchmarking an idea, search the mechanism and aliases here. Cite the existing ID and state the material difference from prior attempts: changed mechanism, workload, correctness contract or stronger measurement. Record renamed branches as aliases of the existing idea. If an earlier patch exists, inspect it before rebuilding it.

Append a retry to the existing row, preserving the negative or inconclusive history. Record the runtime, baseline and candidate revisions, input state, exact work/output checks, measurement conditions, result, uncertainty and adoption status with a receipt. A correctness pass, favorable pilot, hardware capture and calibrated price are different claims. Report overlapping bundles as combined results. Compare throughput using equal work and matching timing models.

Use a new ID only for a materially different mechanism or validation question and link the related IDs. Keep IDs stable permanently. If new evidence contradicts an entry, update its outcome and preserve the superseded observation with its conditions. Link older plans here for current status. Experiment proposals remain proposals until explicitly selected for work.
