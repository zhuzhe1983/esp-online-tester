# C5 CPU memory policy helper

The new private module models the source-backed C5 PMA/PMP subset before any shared execution-path wiring. The [source receipt](sources.json) pins IDF5.5.3/5.5.4, C5 TRM1.1 and privileged ISA1.10; the PMA/PMP source/macros are byte-identical across these IDF releases. Original LCD273 typed code at420713ac supplies the request fixture. No third-party binary or downloaded source body is committed.

The helper owns 52 CSRs with fixed arrays. PMA TYPE is valid/invalid memory, not a bypass enable. OFF/TOR/NAPOT and RWX are evaluated independently of privilege, with real sticky LOCK behavior. PMP uses the lowest matching entry, checks the complete access, and applies locked permissions to the guarded Machine profile; a locked TOR freezes its predecessor address. Illegal writes do not partially commit. Locked fields are ignored before validating a new value, so an invalid replacement cannot unlock them. Raw ROM/profile replacement has no reset operation here; only `reset_core()` clears locks.

`GuardedMachineContext::new(machine_only, mprv)` requires a reliable caller machine-only guard and MPRV=false. It never interprets MPP as current mode. CPU accesses are Fetch, Load, Store, AtomicRead (LR), AtomicWrite (SC), and AtomicRmw, with X/R/W/R/W/RW permissions. A helper allow or no-match result must still pass other policy layers and existing Bus/APM/address gates. The helper does not grant MMIO atomic support, apply policy to DMA, implement reservation state, or substitute for any bus device.

The live owner and immutable `SnapshotV1` expose the same `check_pma`/`check_pmp` methods through one private read-only view. Snapshot fields have read-only getters, and an access does not copy or allocate a snapshot. Epoch/generation changes let a CPU monitor copy only after committed policy changes or core reset. Same-value and locked ignored writes do not change generation. No snapshot restore/user-metadata constructor is exposed.

POR80000000/A2 contradicts the TRM feature list excluding NA4. It remains a tagged unqualified state with a conservative low128B unsupported window; guest NA4 is rejected. Unknown unaligned TOR edge/tail and subgrain NAPOT behavior is unsupported only in the affected window, preserving unrelated known mappings. PMA overlaps, unknown predecessor-lock propagation and unsupported PMP XL are explicit limits. Ambiguous address-CSR WARL readback is also unsupported; the raw snapshot still reports the requested value. The original address writes are CSRRW rd=x0, so checked execution glue must preserve the no-old-read rule. Cache attributes are diagnostics of a coherent no-line model, without physical cache, tap, or latency claims.

[Verification](checks.json) reports 20 passing independent tests (2 internal and 18 contract cases), plus harness all-targets Clippy with warnings denied. Cargo metadata confirms one package and zero dependencies; no full emulator build is needed. The fixture replays all 64 original PMA write requests and all 16 PMP entries in the non-OCD branch, with original fixed ROM/linker boundaries. H=0 and H=8MiB are explicit PSRAM-heap test inputs, not observations of the guest's dynamic return. Expected accesses cover code/data separation, ROM, XIP/rodata, PSRAM, LP, peripherals, gaps, locks and unknown windows.

Shared Core/state/exec/lib/Bus glue, reliable context publication, pre-side-effect CPU probes, decoded-fetch permission checks and actual original-factory continuation are separate integration work. This change does not run original guest instructions, prove PMA-stage completion, produce LCD output, build WASM, benchmark CPU time or qualify public factory support.

The static normal return is `420716f2`; the direct caller at `42000930` calls the APM wrapper, which tail-jumps at `4206e924`, so the caller's post-call stop is `42000934`. The dynamic H getter is `42006840`, called at `42071650`; observe `a0` at `42071654`. It reads the actual PSRAM initialization/mapping/heap state, not a fixed total capacity. A diagnostic `Debug` snapshot and raw getters require no guest-CSR read or extra instruction execution. Core integration must preserve/reset the policy owner so epoch/generation changes invalidate cached snapshots; raw ROM byte replacement must not call its reset.
