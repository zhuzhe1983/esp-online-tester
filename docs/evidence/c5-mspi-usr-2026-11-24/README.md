# C5 bootloader idle flash Resume

The unchanged LCD273 bootloader sends an ordinary SPI1 USR transaction containing the eight-bit opcode `0x7a`, with no address, dummy clocks or payload. The retained original-image baseline stops at this request:526846 instructions,526784 nominal cycles, faulting store PC`0x4084e7ac` to`0x60003000`,400 UART bytes, zero nonzero pixels and zero SD commands. This change models that specific awake, idle NOR case. A new factory run after integration is still required; these module tests do not establish app, LCD or TF execution.

The exact request has PCR MSPI configuration`0x5` (readback`0xd`), clock`0x605`, SPI1 CTRL`0x00200000`, USER`0x80000000`, USER2`0x7000007a`, MOSI/MISO lengths zero, MISC`0x2` and DTR`0x20`. The disabled data phases make their encoded lengths irrelevant. The existing actual PLL-ready observation and all PCR gates still apply. No ROM cookie or unconditional source readiness is added.

The factory uses IDF v5.5.3, commit`2c211b236707889e8400c4dc5644dd5c4ee071e0`. Its [C5 bootloader flash setup](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/bootloader_support/bootloader_flash/src/bootloader_flash_config_esp32c5.c) calls `bootloader_execute_flash_command(CMD_RESUME,0,0,0)` and then waits for idle. The [private header](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/bootloader_support/bootloader_flash/include/bootloader_flash_priv.h) defines CMD_RESUME as`0x7a`. The [shared bootloader helper](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/bootloader_support/bootloader_flash/src/bootloader_flash.c) matches the typed original helper at`0x4084e5f4`: it saves controller settings, programs the requested phases, starts USR, polls the command and restores settings. No alternate Resume opcode is inferred.

IDF v5.5.4 at`735507283d5b2f9fb363a1901172dbd9e847945d` retains these Resume/helper semantics. It adds an optional `CONFIG_BOOTLOADER_FLASH_DC_AWARE` reset before Resume in C5 setup. The common file also changes a C6 rev0 read workaround, outside this C5 command path. The private header and generic flash driver are byte-identical between the two versions; full-file hashes and the differing files are recorded in checks.json. The generic driver uses Suspend`0x75`, Resume`0x7a` and status-register-2 mask`0x80`; that source does not make a suspended engine exist in this emulator.

[XMC XM25QH256C Rev2.1](https://www.xmcwh.com/uploads/2026-11-12/XM25QH256C_Ver2.1.pdf), issue date2025-02-14, sections7.2.36 and7.2.52, documents two relevant behaviors: Resume is ignored when SUS is zero or BUSY is one, and a command other than Reset`0x99` cancels a preceding Reset Enable`0x66`. The implemented subset requires SUS15=0, BUSY0=0 and no pending command. It preserves live status, WEL, buffers, controller RD_STATUS, MMU, flash and PSRAM bytes, and cancels the flash Reset Enable latch only when the command actually reaches CS0. Existing virtual JEDEC`20/40/19` for32MiB is compatible with the IDF XMC identification family; this datasheet reference is a virtual-device contract, not identification of the physical Waveshare package.

The shared array engine performs program and erase synchronously, with no deferred or suspended job. The new command therefore has no operation to resume. It bypasses that engine explicitly rather than accepting an unknown opcode through its default branch. A valid transaction raises only the existing controller mask`0x18`. The fixed [C5 SPI1 header](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/register/soc/spi1_mem_reg.h) names these bits SLV_ST_END3 (CS returning high) and MST_ST_END4. Auto Resume PER_END0, Auto Suspend PES_END1 and WPE_END2 remain unchanged. No successful Auto Resume event, clearing of a fake busy bit, asynchronous flash latency or physical timing accuracy is claimed.

Only command-only SPI/STR, eight-bit Resume on CS0 alone is added. Active BUSY, SUS, a pending command, deep power-down, payload/address/dummy phases, FLASH_PE, malformed command length, DTR, quad command encoding, held CS and missing clocks reject without observable side effects. Suspend`0x75`, alternate`0x30`, unknown`0x7b`, SPI0 USR and unknown engines remain unsupported. Existing no-CS and CS1 no-response paths retain their behavior and cannot change flash state or its Reset Enable latch. The bounded idle case does not implement a general suspended-operation lifecycle.

Fifteen MSPI unit tests and seven PSRAM regression tests pass. Four new tests reproduce the actual32MiBFlash/8MiBPSRAM request, preserve all backing bytes and status/WEL/buffers, read the real status afterward, resume after an actual synchronous page program, check22 unsupported cases transactionally, and check reset-latch/CS routing. One initial test incorrectly expected the existing CS1 no-response path to reject; correcting that assertion preserved the existing transport contract. The controller-reset test was renamed to avoid the CI `external_` substring filter. Isolated MSPI/register/QuadPSRAM Clippy passes with warnings denied. The longer original SRAM PSRAM guest was explicitly filtered from this focused run. Unrelated unwired clock/analog APIs in this isolated base produce library dead-code warnings during the PSRAM integration build; no allowances were added, and the owned-module Clippy check is clean.

No bus/soc/shared engine, per-tick path, firmware or image validation was changed. Public source pins, hashes, exact register values and aggregate checks are retained here; raw source files, the manufacturer PDF and the baseline log remain in the ignored common cache. Raw local paths and process/session details are omitted from committed evidence.
