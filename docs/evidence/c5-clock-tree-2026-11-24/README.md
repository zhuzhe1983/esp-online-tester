# C5 functional clocks and RTC calibration

Sources are fixed ESP-IDF v5.5.3 `2c211b236707889e8400c4dc5644dd5c4ee071e0`, checked against v5.5.4 `735507283d5b2f9fb363a1901172dbd9e847945d`. See `sources.json` for exact URLs, original byte hashes and fetch metadata. TRM1.1 sections9.2.4.1 and9.3.1 require an update transaction for root/CPU/AHB selection. The APB divider is bits15:8; bits7:0 control a distinct optional idle decrease. APB changes have no BUS_CLOCK_UPDATE trigger.

The legacy constructor keeps XTAL-only reads/writes. The documented APB field bug is corrected. An explicit virtual profile accepts pending root/CPU/AHB settings and atomically commits only a valid available source and an integer CPU/AHB ratio with AHB at most48MHz. The update command self-clears after the state is actually applied. PLL availability is an external observation of the independent analog engine; this module never creates CAL_DONE. A source that loses readiness has an unknown functional frequency.

The declared virtual RC_FAST rate is17.5MHz only when the actual analog power input is on, LP FOSC is tuned to100 and its HP gate is open. RC_SLOW136kHz requires an actual DIG_REG byte of128 supplied by the analog engine. Unknown or unwritten bytes never become a configured clock. LP FOSC retains the documented POR172 until the guest writes100; other tuning values reject. LP_FAST stays XTAL/2=24MHz while the SWD pulse model depends on that clock. External slow sources remain absent.

This is functional frequency configuration on the existing nominal240MHz scheduler. Neither CPU instruction duration, oscillator jitter, analog lock time, cross-domain latency nor physical DFS timing is modeled here. Guest mcycle adjustment is independent of monotonic peripheral time. CPU-only reset retains clocks, HP reset clears PCR, LP reset clears LP mux/tuning, analog reset clears both; opt-in selection remains active until explicitly disabled. Disabled/raw-ROM/SRAM selection has no active virtual-clock state or deadlines.

TIMG0 RTC calibration is a separate engine. Exact addresses are PCR TG0 configuration `0x60096054`, source/prescaler `0x60096130`, reference XTAL gate/reset `0x60096160`, and TIMG0 configuration/result/timeout `0x60008068/0x6000806c/0x60008080`. It counts MAX selected-source edges and reference48MHz edges, with finite deadlines and sub-edge remainders. RC_FAST calibration uses the actual source divided by FOSC_TICK_NUM+1, including the driver's32 divider. RDY and VALUE appear only after the counters finish; an absent or unconfigured source times out when the reference count exceeds THRES. Read-only status/result writes cannot complete it. APB gating blocks accesses while the independent reference domain can keep measuring; reference gating pauses the calibration counters.

Periodic measurement, timeout reset cooldown, restarts, source changes and resets are explicit state transitions. Software START clears old status; automatic periodic windows leave result/timeout observations latched. Each functional measurement starts its counter phases at zero; a source/prescaler switch resets its partial phase while preserving whole counted edges. These are declared functional synchronization policies, not measured crossing latency or phase noise. Whole stable periodic windows aggregate arithmetically, so a large guest-time jump does not loop once per measurement. General TIMG0 timer/watchdog registers, interrupt routing, external32k inputs, LP_TIMER and dynamic physical CPU timing remain absent and unknown accesses still fault.
