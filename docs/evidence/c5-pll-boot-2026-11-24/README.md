# C5 targeted analog bytes and finite virtual PLL calibration

The unchanged LCD273 bootloader's `rtc_clk_init` writes DIG_REG and BBPLL through the actual HP REGI2C controller. This extension adds those targeted byte transfers and a finite functional PLL lifecycle. It does not replace a guest function or supply a constant ready result. The pre-integration original-firmware boundary remains423328 instructions, PC`0x4084c924` reading FOSC`0x600b0418`, with229 UART bytes, SAR3reads/3writes and no app/pixels/SD commands. New DIG/PLL results below are focused register-driven checks; the parent must wire clock/time dependencies and rerun the original image.

## Explicit virtual inputs

Public headers name these internal analog byte fields without publishing their POR values. This profile declares DIG bytes reg5=0, reg7=0, reg13=`0x0c`, reg14=0, and the five BBPLL bytes all0. Unimplemented bits are configured0 and must be preserved by writes. These are virtual USB3V3 profile values, not measured/default silicon values. DIG13 therefore changes through real masked guest transfers `0c ->08 ->00`; DCAP becomes128 only after a real write. No regulator voltage, RF, PHY, ADC or battery behavior is reconstructed from those control bits.

PMU command latches initially model PLL power/output off; WT-word reset0 alone does not establish their physical silicon latch state. The guest must actually issue the documented power commands. FOSC's R/W field reset and ANA_CONF0's register reset are header-backed, separate from those virtual byte/latch choices.

No measured PLL locking duration is available. The named virtual profile chooses **100us=24000 cycles on the emulator's nominal240MHz timeline**. This is a functional settling input, not a measured oscillator, jitter, ramp or silicon calibration result. The real guest10us delay still executes; no additional precision claim or host delay substitution is made for the physical post-DONE settling waveform.

## Lifecycle and strict boundaries

Calibration requires the enabled strict-ROM profile, the three BBPLL power latches, the real master/APB/I2C gates, the BBPLL route, the complete supported byte configuration and an actual HIGH-clear/LOW-set request. Its deadline starts only when these prerequisites hold. Polling does not move time or create work. At elapsed virtual time, the engine derives CAL_DONE and records one completed lock. `pll_ready()` remains false until the guest actually clears LOW and then sets HIGH; it also requires valid bytes, power and the global output gate.

Incomplete/changed accepted configuration, power-down, premature stop, routing or master-clock loss before completion cancel pending calibration. Valid reconfiguration/restart requires another complete finite interval. Invalid unknown-field writes reject transactionally. A completed stopped oscillator can keep running after the I2C controller is gated or redirected; output gating changes usable readiness without inventing a new lock. Power-down clears lock/DONE. Reads of BBPLL reg8 OR_LOCK/calibration internals remain unsupported rather than fabricated.

Writable targeted masks are DIG5/7:`80`, DIG13:`0c`, DIG14:`ff`; BBPLL2:`7f`,3:`ff`,5:`77`,6:`f0`,9:`03`. Unknown slaves/registers/bits reject. Known alternative field values are retained as actual configuration but cannot complete this48MHz/480MHz-only engine. Controller BUSY is clear only after the real synchronous byte operation; counters count accepted transfers, not status reads. SAR retains its separate PMU reset/power prerequisites.

## API, selection and reset contract

`enable_virtual_pll(cycle)` is only for the exact validated ROM profile. `disable_virtual_pll()` cancels deadlines/lock/DONE and makes all clock input getters false/None while retaining guest bytes. Old SAR `read`/`write` methods remain; `read_at(address,cycle)` and `write_at(address,value,cycle)` pump before MMIO. `pump(cycle)` and absolute `deadline()` integrate with parent scheduling. New routed addresses are`0x600b00ac`, `0x600b00cc` and`0x600af818`; existing master command windows handle the two new slaves.

Pure getters are `pll_ready()`, `rc_fast_powered()` and `slow_dcap()->Option<u8>`. The latter returnsNone until a real DIG14 write, then the actual byte; reads alone never mark it configured. LP source mux, tuning, divider and calibration ownership stays in the separate clock module. With this profile disabled, the previous report is byte-identical and autonomous work is absent.

CPU-only reset retains state. HP digital controller reset keeps analog bytes/power/DCAP but resets calibration command/acknowledgement/readiness for a new actual START/STOP. LP reset also restores modeled PMU power controls; analog reset restores the declared byte profile and transfer diagnostics. Dropping the digital acknowledgement is a conservative functional reset contract, not a claim of measured physical lock loss or undocumented analog latch reset precision. Strict profile selection persists across those explicit resets; SRAM/raw-ROM selection must deselect it through parent loader glue.
