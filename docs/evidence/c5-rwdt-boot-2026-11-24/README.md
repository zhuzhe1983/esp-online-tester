# C5 RTC watchdog stage engine

The retained unchanged LCD273 factory run reaches573867 instructions and582 UART bytes, including QIO,80MHz and32MB flash messages. It stops at ROM PC`0x40021216`, storing`0x4007ea00` to LP_WDT_CONFIG0`0x600b1c00`; the prior value is`0x0007ea00`. This sets stage0 action4 while both EN31 and Flashboot12 are clear. The new engine accepts that inactive configuration and implements subsequent real clocked counting, feed, interrupt and logical reset actions. A post-integration original-image run remains required; zero pixels/SD commands at the retained boundary do not establish app, LCD or TF execution.

Sources are fixed IDF v5.5.3`2c211b236707889e8400c4dc5644dd5c4ee071e0` (the factory version), checked against v5.5.4`735507283d5b2f9fb363a1901172dbd9e847945d`, plus [C5 TRM1.1](https://documentation.espressif.com/esp32-c5_technical_reference_manual_en.pdf) sections9.1 and16.2 and registers16.1–16.13. The watchdog register/struct/LL, LP_CLKRST and interrupt headers used here are byte-identical across those versions. [bootloader_init.c](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/bootloader_support/src/bootloader_init.c) and [wdt_hal_iram.c](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/hal/wdt_hal_iram.c) are also byte-identical: the bootloader clears flashboot protection, initializes RWDT, configures stage0 system reset, then the HAL actually feeds before enabling it. No host-side feed or ROM interception substitutes for these guest operations.

The model uses four stages in a loop. Each timeout clears the count and advances the stage. Actions0/1/2/3/4 mean no action/interrupt/HP CPU reset/HP core reset/system reset according to the C5 register header and TRM. Legacy LL names RESET_SYSTEM3 and RESET_RTC4 do not rename C5 reset domains. Stage0 requires `hold << (WDT_DELAY_SEL+1)` source ticks; the other stages use their raw hold values. Flashboot12 independently activates RWDT and forces stage0 system-reset protection, even if EN31 is clear. Disabling stops counting; it does not invent a feed. Only a protected FEED31 write restarts stage0/count, and that write does not clear a latched IRQ or retract an already emitted reset.

Write protection uses the actual key`0x50d83aa1`. Locked RWDT config, holds, feed and RWDT interrupt writes are ignored. SWD's independent key and existing shared-interrupt behavior are preserved. Interrupt raw/enable/status use RWDT bit31 and SWD bit30; RAW/CLR are write-one-to-clear and the status is masked. The evaluated C5 enum maps their shared LP_WDT interrupt to source18. No new interrupt source or older-chip alias is introduced.

The API is `enable_virtual_rwdt(cycle, delay_sel)->bool`, `disable_virtual_rwdt()`, `set_slow_clock(cycle, Option<hz>)->bool`, `set_cpu_reset_enabled(bool)`, the existing combined `pump(cycle)`/`deadline`, and `take_reset_cause()->Option<LpWdtReset>`. The enum is Swd/RwdtCpu/RwdtCore/RwdtSystem; `reason()` returns`0x12/0x0d/0x09/0x10`, respectively, from TRM Table9.1-1. Production integration consumes the typed accessor; the older SWD-only `take_reset()->bool` is now test-only. Only the strict validated-ROM path selects the RWDT profile; SRAM/raw-ROM deselection disables it.

RTC slow frequency is supplied by the separate clock model. There is no136kHz fallback. That virtual rate becomes available only after the actual DIG_REG DCAP128 configuration and matching LP clock selection. The cold prefix with an unknown/uncalibrated source produces no reconstructed ticks; complete physical POR watchdog timing is outside this bounded profile. A new guest active enable with no known rate rejects. Inactive stage configuration still works without a rate. Source withdrawal freezes the count and removes its deadline while preserving registers, IRQ state and count; it does not feed or disable the readable timer. A changed source is refused while a reset remains pending, so the owner must drain/apply that event before retrying the observation.

Time uses the existing nominal240MHz scheduler with integer fractional source-tick phase. Pumping advances using the old rate before changing it; irregular pump partitions and supplied rate changes retain that phase. All-OFF and IRQ-only complete four-stage loops aggregate arithmetically. A reset-producing path reaches one pending reset within at most four stage transitions and stops until consumed; no reset queue or catch-up reset storm is generated. Active zero hold thresholds are explicitly unsupported and reject before mutation, rather than choosing undocumented zero/wrap behavior. Missing/zero/above-timebase source rates, actions5–7, APPCPU debug enable and analog chip-reset mode also reject. Light/deep-sleep behavior and physical source-edge mux transients are outside the supported awake functional profile.

CPU reset additionally requires both LP_WDT_PROCPU_RESET_EN11 and the supplied separate LP_CLKRST CPU-reset permission; that observation defaults false. The fixed [LP_CLKRST header](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/register/soc/lp_clkrst_reg.h) defines permission bit25 as0=deny/1=allow, default0. TRM register9.91 reverses its polarity/default. This lane keeps that conflict explicit and owns no LP_CLKRST register routing. CPU/core configured pulse codes are retained as raw three-bit values in pending diagnostics; system reset has no invented pulse value. LL nanosecond names and header LP_DYN_FAST_CLK units do not establish a physical conversion here. CPU-stall and reset pulse timing remain unmodeled; integration applies the logical reset at its deadline.

CPU/core reset preserves LP watchdog count, stage, source phase and pending state. LP/system reset clears its controller; supplied clock/reset-permission observations survive a controller-only reset and must be refreshed from the actual clock/reset owner. Analog reset removes the slow-rate/CPU permission observation. Existing SWD analog retention remains unchanged. The owner must use the combined deadlines, consume typed reset causes and apply the corresponding domains. SWD wins when SWD and RWDT reset together, matching Table9.1-1.

The pure eFuse getter `wdt_delay_sel()` reads actual decoded DATA0 at eFuse+`0x30`, bits28:27, matching [efuse_reg.h](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/register/soc/efuse_reg.h), [CSV BLOCK0 bits59–60](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/efuse/esp32c5/esp_efuse_table.csv), and unchanged ROM instructions`0x4002121c..0x40021228`. The C5 LL incorrectly names DATA1 in this calculation. The getter follows the actual header/CSV/ROM field, with no fuse-profile change; the existing unprovisioned virtual profile returns0. Tests vary the logical OTP/reload and verify all four values while keeping DATA1 different.

Twenty watchdog tests, including all eight unchanged SWD tests, and seven eFuse tests pass. The final owned-module harness runs all27 tests and passes Clippy with warnings denied and no allowances. Two existing default C5Bus watchdog regressions also pass, preserving strict profile-off behavior. Checks include the exact observed inactive store, actual feed/enable, independent keys, stage0 multipliers, all three reset actions and CPU gating, source loss/rate changes, fractional stage-loop catch-up, one billion IRQ/OFF loops, u64 maximum time, zero-threshold rejection, reset retention, late-feed behavior and shared IRQ priority. The612000 hold in the configuration test is a test vector, not a claim about a future factory write.

No bus/soc/shared per-tick code, transport, firmware byte or image validation was changed. Parent wiring and original-image acceptance remain separate. The isolated legacy integration build warns about unwired profile APIs in this base; no warning suppression was added. Public source hashes and aggregate outcomes are committed; raw logs, fixed-source cache and local build paths stay in the ignored common cache/target.

## Integrated checkpoint

The preceding module-only scope is the original standalone change. Its subsequent Bus/Soc integration is recorded in `integration-checks.json`, with exact checked source hashes, unchanged inputs, commands and log hashes. All211 C5 tests pass with developer inputs available, and both workspace/native and release-WASM Clippy pass with warnings denied. The focused release suite explicitly disables LTO; full default-LTO workspace testing and final product acceptance remain pending.

The unchanged factory now actually configures `0xc007ea00`, hold0 `612000`, feeds once and locks the RWDT key. It proceeds to573914 instructions/582 UART bytes before the next real fault: PC`0x400212f2` writing TIMG0 WDT protection at`0x60008064`. No application, LCD or TF execution is inferred.

The integration keeps a dispatched reset stable until reboot applies its domains, including simultaneous SWD/RWDT priority. Profile selection/exit invalidates IRQ state, and both ROM loaders reject replacing a ROM while a dispatched reset remains unapplied. Four Bus regressions exercise actual DIG REGI2C DCAP clock inputs, IRQ source18/CLIC input23, Core/LP retention, source loss, raw-ROM deselection and reset priority. The existing input-dependent SWD fixture additionally checks both ROM loaders' pending-reset rejection.
