# C5 observed SPI2 and LEDC clocks

This change prepares independent transport support for actual clock observations. It does not establish that the original Waveshare ESP32-C5-LCD-2.73 factory firmware reaches SPI2, LEDC or its application. The starting revision is `f20a0241`. No firmware, browser or CPU benchmark was run for this transport change.

The fixed ESP-IDF v5.5.3 revision is `2c211b236707889e8400c4dc5644dd5c4ee071e0`; v5.5.4 is `735507283d5b2f9fb363a1901172dbd9e847945d`. Fresh full-file comparisons found identical PCR, SPI LL, LEDC LL and clock-definition files. Exact URLs, fetch times, byte counts and hashes are in [sources.json](sources.json).

- [C5 PCR register header, IDF v5.5.3](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/register/soc/pcr_reg.h): SPI2 source bits21:20 select XTAL, PLL160, RC_FAST and PLL120; bit22 enables the function clock. Divider bits19:12 are applied before the existing SPI_CLOCK wire divider. LEDC source bits21:20 select XTAL, RC_FAST and PLL80; selector3 remains unsupported.
- [C5 SPI LL, IDF v5.5.3](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/hal/esp32c5/include/hal/spi_ll.h): `spi_ll_set_clk_source` and `spi_ll_set_clk_source_div` confirm the source encoding and `mst_div - 1` register value.
- [C5 LEDC LL, IDF v5.5.3](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/hal/esp32c5/include/hal/ledc_ll.h) and [clock definitions](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/include/soc/clk_tree_defs.h) confirm the three LEDC sources. RC_FAST is supplied by the independent clock engine rather than assigned a default rate in transport.

`Transport::set_clock_sources(cycle, rc_fast_hz, pll_ready)` starts with `None/false`. Zero RC_FAST is unavailable. Only the caller's actual source observations can enable the additional sources; PCR selections, ROM cookies and elapsed host time do not grant readiness. The integration caller must take the transport box, apply observations at the source boundary, call `publish_pwm` with the bus, restore the box and mark IRQ state dirty. Source loss must also be supplied, including explicit clock-profile disable. Bus, SoC and profile selection are outside this change.

An accepted SPI transaction records its source frequency. A selected-source change or loss cancels all pending functional work, including a request waiting for GDMA. Cancellation preserves programmed clock bits, clears USR busy and the byte transaction, and does not call the board, increment transfer totals or manufacture TRANS_DONE. Rejected USR commands continue to increment `rejected`; cancellation does not change that counter. An unrelated source event preserves the accepted transaction. The selected source and PCR divider feed the existing conservative serial-time floor; FIFO/setup, contention, DDR, slave operation and partial-byte transmission remain unmodeled.

The unchanged `None/false` path retains the previous CPU/3 LEDC progression, deadline and report string, including the static-duty latch at CPU cycle5121 in the existing XTAL fixture. On the first real observation, the previous source first receives every uncharged CPU cycle. Thereafter each elapsed interval contributes `delta / 3 * hz` plus `((delta % 3) * hz + fraction) / 3` to the shared LEDC phase; numerator modulo3 is retained across source and gate boundaries. No sub-tick is discarded or charged to a later source. The scheduler remains nominal240MHz and the LEDC reference80MHz; this is functional timing, not physical DFS or analog oscillator accuracy.

The shared LEDC deadline API rounds to reference ticks. The additional-source path schedules the earliest possible CPU-cycle boundary and rechecks at most two cycles later, so a pending static duty is neither latched early nor delayed by that rounding when the caller pumps scheduled boundaries. Oversized caller advances can still skip the exact publication instant, as with existing peripherals. Timer counts, duty and frequency use the actual selected source. LCD147 verifies a real LEDC-routed board backlight. LCD2.73 instead uses the separate CH32V006 I2C register5 brightness protocol; the unchanged LCD2.73 regression verifies that boundary without treating CH32 brightness as LEDC output.

The eight clock tests exercise the Transport component with explicit caller-supplied source observations. Transport-owned register helpers take the transport box, call `Transport::read` or `write`, pump and restore it. GPIO/memory accesses, virtual scheduling, DMA and board callbacks retain the real `C5Bus`. This keeps component inputs separate from the production bus's actual analog/clock-provider observations: the fixture grants no production PLL readiness and changes no production clock owner. The numeric phase, wire-time, cancellation and board-output assertions remain in place. Native integration checks must independently establish the real provider's readiness and profile-selection rules.

Initial validation at `84a3820abff966fead9855e85d77f7643198736d` used Rust1.100.0 stable, release mode and one build job. Results and independently calculated numeric samples are in [checks.json](checks.json): eight new tests;101 C5 unit tests; eight existing transport tests; two existing LCD2.73 tests passed. Strict package Clippy with warnings denied failed on seven `dead_code` diagnostic groups because the starting revision's analog/clock profile and the new transport setter still needed production integration. A separate diagnostic run with command-line `-A dead_code` passed. The component-boundary fixture follow-up reran all eight clock tests and that diagnostic Clippy successfully. No source-level lint allowance was added; strict integrated Clippy remains required. Evidence privacy and `git diff --check` passed.
