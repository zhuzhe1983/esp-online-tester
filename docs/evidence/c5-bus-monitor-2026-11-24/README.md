# C5 bus monitor source contract

This private block uses ESP-IDF v5.5.4 `735507283d5b2f9fb363a1901172dbd9e847945d`, matching the factory image. Sources were read before implementation: [C5 register definitions](https://github.com/espressif/esp-idf/blob/735507283d5b2f9fb363a1901172dbd9e847945d/components/soc/esp32c5/register/soc/bus_monitor_reg.h), [C5 low-level driver](https://github.com/espressif/esp-idf/blob/735507283d5b2f9fb363a1901172dbd9e847945d/components/hal/esp32c5/include/hal/assist_debug_ll.h), [PCR definitions](https://github.com/espressif/esp-idf/blob/735507283d5b2f9fb363a1901172dbd9e847945d/components/soc/esp32c5/register/soc/pcr_reg.h), [interrupt enum](https://github.com/espressif/esp-idf/blob/735507283d5b2f9fb363a1901172dbd9e847945d/components/soc/esp32c5/include/soc/interrupts.h) and [TRM v1.1](https://documentation.espressif.com/esp32-c5_technical_reference_manual_en.pdf), chapters9 and20.

The block base is`0x600c2000`, IRQ source27, and PCR_ASSIST gate/reset register`0x60096100` (clock bit0 reset0, reset bit1 reset0). RCD_EN+`0x44` has RECORDEN bit0 and PDEBUGEN bit1; both must be set to update reset PC/SP captures. PC/SP values come only from actual typed execution samples. The internal CLOCK_GATE+`0x108` is register autogating (reset1), not an external off switch. Four monitored region bounds default to empty (min`0xffffffff`, max0); SP defaults to0..`0xffffffff`. DATE defaults34640176.

The C5 LL's explicit pseudo-RTL is essential: RAW reports the current condition masked by MONTR_ENA; the hidden interrupt-state flops sample RAW & INTR_ENA. CLR clears those flops but does not clear software-readable RAW. This is not the ordinary sticky RAW/INT_ST register scheme. The shared S31/C6 implementation is not reused.

TRM9.1 distinguishes CPU Reset (CPU only), Core Reset (HP digital system/peripherals), System Reset (including LP) and Chip Reset. TRM20.5.2, printed pp814–815, explicitly preserves PDEBUGPC/SP across the HP CPU reset while clearing RCD_EN. The implementation must distinguish CPU-only reset from peripheral/Core Reset, preserve the special reset captures across HP reset, and clear them on POR or explicit PCR module reset. Broader System/LP-reset capture retention is not established by this source audit and remains outside this block's reset API.

Existing hooks were researched before proposing integration: `emu_core::Bus::note_pc` receives exact per-instruction PC in RV32 interpreter and block paths, but no SP. `esp_soc::Observer<C5>` with `Wants::INSN` already receives the concrete Cpu and bus in `on_insn`, so the C5-only integration can supply actual `cpu.x[2]` without a shared Core/Bus change. C5's separate Bringup runner needs its own typed sample. Do not follow a full sample with a second PC-only/None-SP sample. CPU access observation must explicitly exclude instruction fetches, DMA and host accesses.

Open upstream [PR335](https://github.com/mikroverk/esp32sim/pull/335) was inspected at its current head before this interface decision. Its sole runtime change adds an inline request to `step_outcome`; it adds no observer API or SP sample hook. No shared observer is proposed or modified by this lane.

The module exports `C5BusMonitor::new/contains/read/write`, `observe_cpu(pc, Option<sp>)`, `observe_access(CpuAccess)`, `observe_exception(pc)`, `cpu_reset()`, `core_reset()`, `irq()` and `source()`. Addresses are absolute. `CpuAccess` explicitly supplies Data/Peripheral bus, address, byte width, direction and actual PC/SP. Aligned1/2/4-byte transfers match inclusive byte ranges; instruction fetch, DMA, host and LP traffic must never be submitted as HP CPU accesses. Invalid samples reject without producing captures or IRQs.

Recording requires both RCD bits. Region PC/SP captures require PDEBUGEN; SP bound conditions can still be monitored with PC output disabled, but no PC is fabricated. Missing SP returns an incomplete-observation result, makes an attempted SP capture unavailable through `read()->None`, and makes RAW unavailable when active SP monitoring cannot be evaluated. A later complete CPU sample restores known status. Configuration writes alone never synthesize a PC/SP capture. Reset capture registers have their documented zero values on a fresh POR/PCR reset; this is not evidence that a CPU sample was captured.

The functional observation clock is the actual CPU sample/transfer boundary, not a cycle-accurate hardware waveform. Each CPU sample clears the preceding access pulse, updates the live SP condition, and samples hidden IRQ state. A matching bus transfer supplies a real region condition/capture. CLR clears only hidden IRQ bits; an unchanged violating condition remains visible in RAW and reasserts IRQ on the next real observation. Normalizing SP or ending an access pulse removes RAW and the next sampled IRQ. No INT_ST register is invented.

PCR_ASSIST bit0 is specifically the bus gate in the C5 LL. TRM9.2 supplies the functional Debug Assistant from CPU_CLK (and associates its functional gating with the HP CPU). Therefore, gating APB prevents successful register transactions but does not freeze real CPU-context observations; actual execution supplies those clock observations. The internal register autogating bit also does not stop capture. Holding PCR reset clears actual block state and prevents observation/configuration until reset is released. The special PC/SP retention across HP reset is not applied to explicit PCR reset: PCR reset clears captures according to the module-reset contract, rather than inferring vendor intent from the ROM's reset sequence.

CPU-only reset clears RCD_EN and invalidates current CPU inputs while retaining peripheral configuration and reset captures. HP Core Reset resets peripheral/PCR control, monitor/status and bounds while retaining only the explicit PDEBUGPC/SP capture exception. POR constructs a fresh cleared block. No whole-System/LP-reset capture policy is inferred; the caller must not silently apply CPU-only retention to every reset cause.

Implemented registers are MONTR_ENA/RAW/INTR_ENA/CLR, four region bound pairs, region PC/SP, SP bounds/spill PC, RCD_EN and reset PC/SP, actual exception PC, inactive debug-module status, register autogating and DATE. Memory-stall timeout engines at+`0x100/104` stay at reset and reject nonzero settings. Trace/CPU-DMA memory logging, debugger execution, unknown/unaligned offsets and unknown monitor engines reject; no general register RAM is used. The exception PC callback requires the actual pre-exception instruction, not a trap-vector PC.

Ten focused tests cover exact reset/enables, real PC/SP capture and missing context, every region bus/direction bit, inclusive boundaries/transfer bytes, live RAW versus clear/hidden IRQ, next-sample reassertion, APB versus functional observation, PCR reset, CPU/Core reset retention, actual exception capture, masks and rejected engines/accesses. Source hashes, PR335 head and final checks are retained in `checks.json`. Standalone module Clippy with warnings denied passes. Bus/observer integration, real guest monitor IRQ delivery, full workspace checks, factory execution and benchmarks remain integration work.

## CPU versus Core reset integration

The bus reset dispatcher now preserves HP/LP/analog peripherals for the six documented CPU-only causes. Only core-local CLIC state, active CPU context and the requested-reset flag reset; the common Machine resets the CPU. SRAM app-direct still recopies its selected image under its existing explicit host-restart contract. All eight documented HP Core causes preserve monitor PC/SP while resetting other monitor controls; System/LP retention remains unclaimed. [Reset checks](reset-domain-checks.json) verify real guest captures, retained UART RX FIFO, interrupt matrix routes and LP scratch state, and distinguish cleared live monitor conditions from its sampled IRQ.

## Observer-stop cleanup

A later breakpoint or an earlier after-instruction observer can end the callback chain before the typed monitor clears its context. The shared `Soc::observer_stopped` hook now runs only at those observer-stop returns and clears C5 transient context; its default does nothing for other chips. Native `run` and `run_until_cycle` regressions verify that subsequent host reads/writes cannot create guest captures or IRQ27. A private typed after-observer fixture verifies the opposite callback order. No instruction, console or firmware result is synthesized. [Open-PR inspection](observer-stop-pr-audit.json) found no existing cleanup hook. The foundation receipt records the194-test integration and both Clippy passes; broad release/performance controls still remain.
