# C5 MSPI external clock-source observations

Correction: the PLL FAST_DIV claim below is historical and incorrect. [The source-backed divider correction](../c5-mspi-divider-2026-11-24/README.md) applies NUM+1 to PLL_F480M before the serial divider. The earlier ignored-divider test was changed because it encoded that mistake; its original results and hashes are retained. Other source/gate contracts remain in force.

MSPI now accepts `set_clock_sources(rc_fast_hz:Option<u32>, pll_ready:bool)` from the separate clock/analog model. Defaults areNone/false. The API reports an existing source; it neither powers an oscillator nor enables a ROM compatibility mode. This is integration preparation, not evidence that the factory firmware has executed MSPI on PLL yet. Parent bus/soc wiring and a new original-image run remain required.

The fixed C5 [PCR header](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/register/soc/pcr_reg.h), IDF v5.5.3 `2c211b236707889e8400c4dc5644dd5c4ee071e0`, matches v5.5.4 `735507283d5b2f9fb363a1901172dbd9e847945d`. `PCR_MSPI_CLK_CONF` at`0x6009601c` selects XTAL0, RC_FAST1 or PLL_F480M2; selector3 is unsupported. FAST_DIV7:0 encodes div1/div2/div4 for0/1/2 and applies only to low-speed XTAL/RC_FAST. It is ignored for PLL, including stale low-speed divider bits. Source hashes and additional fixed serial-clock references are in [checks.json](checks.json).

PLL supplies480MHz only when the actual external PLL-ready observation is true and `PCR_MSPI_PLL_CLK_EN` bit2 is enabled. APB/module clock bit0, module reset1, functional gate10 and AXI reset11 retain their checks. RC_FAST uses only the supplied nonzero rate, with the low-speed divider applied; no XTAL fallback or assumed RC rate exists. Unsupported low-speed divider values and missing sources block functional work. PCR configuration remains R/W even when the selected source is absent; commands and mapped accesses then fail.

The existing [SPI1 clock divider](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/register/soc/spi1_mem_reg.h) at+14 and [SPI0 external-RAM clock divider](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/soc/esp32c5/register/soc/spi_mem_c_reg.h) at+50 now receive that actual module rate. Their N divider generates source/(N+1). This gives20MHz from480/24 and80MHz from480/6 in the tests. Existing PSRAM mode, command/address/dummy phases, native pads, capacity and die frequency limits remain enforced; the QuadPSRAM implementation is unchanged.

Withdrawal of source observations immediately prevents commands, XIP translation and PSRAM access. A rejected command does not mutate buffers, status, memory or interrupt state. MMU validity, encrypted-entry rejection, AXI closure and MMU power-down still block mapping independently of source readiness. There is no new waveform, transfer latency or physical flash/PSRAM timing-accuracy claim; the preexisting synchronous functional engine and compatible virtual8MiB die contract remain unchanged.

PCR MSPI module reset clears controller/MMU state while preserving observations supplied by another modeled peripheral, plus the previously preserved XTAL/die/pads. A fresh MSPI object starts with missing external sources; copying PSRAM die state does not invent clock readiness. Parent mode/reset glue must refresh observations from actual retained or reset analog state and clear them for strict SRAM/raw-ROM selection. The ROM compatibility cookie is independent in both directions.

Eleven MSPI unit tests and seven existing PSRAM integration tests pass, and isolated MSPI/register/QuadPSRAM Clippy passes with warnings denied. The longer original SRAM PSRAM guest is outside this focused run; its test was explicitly filtered. New checks cover actual mapped backing bytes, denied/working/lost PLL command paths, RC dividers, ignored PLL low-speed divider bits, every retained PCR gate, reset/die-copy isolation, and genuine PSRAM QPI write/read data at80MHz after20MHz serial setup. Overspeed, pads and opcode checks remain effective. The default missing-source tests remain unchanged and passing.

No bus/soc/transport/shared engine, per-tick work, broad build, benchmark, browser task, firmware byte or validation was changed. Fixed source/raw check records stay in the ignored common cache and isolated target. Committed evidence contains public hashes and aggregate results; absolute workspace paths and raw logs are omitted.
