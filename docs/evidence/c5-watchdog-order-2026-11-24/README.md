# C5 watchdog reset event time ordering

`LpWdt::take_reset_event()` now returns `Option<(LpWdtReset,u64)>`: the actual reset cause and nominal cycle at which it occurred. A late service call must select the earliest unapplied event, then use the C5 reset-source priority only for equal times. SWD therefore wins a simultaneous SWD/RWDT event, while an earlier RWDT wins even if the late call also crossed the SWD deadline. This fixes module-level chronology needed by the separate Bus-level TIMG/LP watchdog arbitration; this commit owns no Bus/Soc or TIMG code.

The sources remain fixed IDF v5.5.3`2c211b236707889e8400c4dc5644dd5c4ee071e0` and v5.5.4`735507283d5b2f9fb363a1901172dbd9e847945d`, with [C5 TRM1.1](https://documentation.espressif.com/esp32-c5_technical_reference_manual_en.pdf) Table9.1-1 and sections16.2–16.3. Table9.1-1 supplies the priority among simultaneous reset sources; its statement about recording the most recent source after separate resets does not authorize discarding an earlier unapplied reset. The owner must first apply that reset, which can change what happens afterward. The existing [RWDT source contract](../c5-rwdt-boot-2026-11-24/README.md) and [virtual SWD contract](../c5-swd-boot-2026-11-24/README.md) remain in force: source-clocked RWDT, explicit nominal240MHz timeline, SWD virtual950ms timeout/850ms request, no physical pulse/stall accuracy claim.

SWD stores a sticky pending timestamp from its actual analog epoch plus EXPIRE, rather than the time of the delayed pump. A real feed pulse completed before expiry legitimately changes a future expiry. A feed, flag-clear write, or later poll after the reset event cannot move or retract its timestamp. RWDT reuses the timestamp already retained in its pending reset record.

Late catch-up uses a fixed-size controller preview. If no reset occurs, the candidate state is adopted. Otherwise the real SWD and RWDT state advances only to the earliest reset timestamp. Future SWD request/flag changes and future RWDT stage actions from the candidate are discarded. Each individual engine already aggregates long periodic intervals arithmetically or stops at its first reset, so preview/replay remains bounded independently of elapsed cycles. No timestamp queue, per-tick loop or reset storm is added. Profile-off pumping returns immediately.

Event consumption marks a dispatch barrier and returns that event once. Further pump/take calls do not advance either watchdog or return another event until the owner applies `reset_domains`; the deadline is None while dispatched. A changed clock observation is refused while any event is pending or dispatched. Register write-trigger behavior and readable configuration remain separate from the immutable event record. Strict profile deselection clears that profile's pending event/barrier and prevents its autonomous timing from leaking into the legacy mode.

The owner passes the actual reset timestamp to `reset_domains`. CPU/Core reset acknowledges already occurred or coincident requests through that timestamp, including a lower-priority LP CPU request covered by another watchdog's Core reset, while preserving the LP count, stage and fractional phase. Future event times are not acknowledged. Reset application does not itself catch up a second interval; any later independent event waits for the next owner pump. LP/System and analog reset retain their prior controller/analog-domain behavior. The interface cannot roll back state that an external caller has already advanced past a different peripheral's earlier reset: Bus arbitration must preview the small controllers together, choose the global first event and commit the real controllers only to that point.

`take_reset_cause()` is now a test-only wrapper around the event API. Production callers must use the timestamped event. The historical test-only SWD `take_reset()->bool` keeps its old pending-read behavior without creating a production dispatch barrier, so the eight SWD controller fixtures remain unchanged. The existing mixed RWDT retention test still checks complete retained hardware state; its expected bookkeeping now explicitly acknowledges the delivered request/barrier and restores the next real deadline after owner reset. No assertion was removed to hide changed timing.

The independent actual-module harness passes all28 watchdog tests with Clippy warnings denied and no allowances. Eight new tests cover RWDT130M before SWD228M, SWD228M before RWDT300M, equal-time SWD priority, exact late-versus-chunk state equality, no future flags or stages leaking from preview, immutable SWD time through feed/flag clear, real completed feed moving a future expiry, dispatch freezing through u64 maximum time, owner reset reopening progress, coincident request acknowledgement and strict deselection. A136kHz test observes a Core event at cycle3530 followed, after real owner reset with preserved phase, by a System event at5295. Existing billion-loop/u64-boundary and all eight SWD fixtures remain passing.

The first harness run passed27/28: the retention fixture expected the dispatch-blocked deadline to remain None after owner reset. Its expectation was corrected to acknowledge the consumed request and recompute the next stage deadline while retaining the full count/phase/state equality assertion. Final28/28 passes.
