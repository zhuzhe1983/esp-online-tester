# C5 PLL divider correction for PSRAM connection checks

The unchanged LCD2.73 factory reaches `s_check_psram_connected` before reading the device ID. Its real SPI1 transactions exit QPI with F5, write `0x5a6b7c8d` to address0 with command02, then read32 bits with command03. The [negative native receipt](../c5-ocode-handshake-2026-11-24/psram-connectivity-probe.json) records all native pads present, SPI mode, valid24-bit address and no dummy cycles. The write left the actual backing array zero; the read returnedFFFFFFFF. The old model calculated120MHz because it ignored PCR FAST_DIV=5 for PLL.

The [fixed C5 flash LL](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/hal/esp32c5/include/hal/spimem_flash_ll.h), IDF v5.5.3 `2c211b236707889e8400c4dc5644dd5c4ee071e0`, selects the480MHz PLL tap and then divides by FAST_DIV_NUM+1. The [C5 MSPI LL](https://github.com/espressif/esp-idf/blob/2c211b236707889e8400c4dc5644dd5c4ee071e0/components/hal/esp32c5/include/hal/mspi_ll.h) sets NUM5 for an80MHz module clock and NUM3 for120MHz. These executable definitions contradict the PCR header's incomplete low-speed-only comment. The original typed instructions set NUM5 at PC408084ac, then SPI1 CLOCK30103 at4080850a for a20MHz slow transaction: `480MHz / 6 / 4 = 20MHz`. The source2 tap remains480MHz;80MHz is the divided module clock.

The flash LL and timing configuration files are identical in v5.5.4 `735507283d5b2f9fb363a1901172dbd9e847945d`. The MSPI LL files differ: v5.5.3 also permits core240MHz/div2; v5.5.4 removes that case and adds a flash user-dummy helper. Both retain the80MHz/div6 and120MHz/div4 setters. [sources.json](sources.json) preserves exact URLs, captured byte counts, hashes and capture limitations. Connector fetch timestamps were not separately recorded and are explicitly unknown. The public TRM1.1 describes SPI0/1 as primarily reserved for internal use; it supplies no more specific divider rule here.

Only the PLL FAST_DIV calculation changes. Actual readiness, PCR gates, chip select, pads, QPI state, address/dummy/data phases, die capacity and frequency limits retain their checks. The header-based low-source subset remains0/1/2→div1/div2/div4. For low-source NUM2, this conflicts with the SDK getter's div3 and has no independent validation; the retained fixture is a compatibility contract, not silicon evidence. NUM0/1 agree between the two interpretations. No additional low-source encodings are enabled.

The previous ignored-PLL-divider statement and its successful fixture are explicitly superseded in the [older clock receipt](../c5-mspi-clock-2026-11-24/README.md). Its earlier fields and test results remain intact. [checks.json](checks.json) records the old file hashes, corrected numeric expectations and the native negative receipt hash.

Sixteen existing and new MSPI component tests pass in an owned harness containing only `mspi.rs`, `mspi_regs.rs` and `quad_psram.rs`, with the unchanged `esp-periph`/`emu-core` dependency sources. The new regression replays the actual F5/02/03 register values. NUM5/N3 gives20MHz and NUM3/N3 gives30MHz; both write and read actual array cells. NUM0/N3 remains120MHz and gets no response. Missing CS1, a23-bit address and unavailable PLL remain negative cases. Component Clippy passes with warnings denied; the standalone harness permits unused items because the production Bus owner is excluded. No production lint allowance is added.

The harness uses Rust1.100.0, ThinLTO, one codegen unit and one test thread. The first attempt to link prebuilt LLVM23 bitcode with Apple LLVM21 failed; letting Rust perform ThinLTO resolved that tooling mismatch. A normal focused reproduction is `CARGO_BUILD_JOBS=1 cargo test --release -p esp32c5 --lib mspi::tests -- --test-threads=1`. Full builds, native factory execution, benchmarks and browser checks were not run in this lane. The parent must rerun the unchanged factory and retain the original memory self-test; component success does not establish that the original8MiB self-test or application now completes.

## Parent integration checkpoint

The unchanged original factory now passes its real SPI write/read check: backing bytes become8d7c6b5a, readback equals5a6b7c8d, the compatible virtual ID is read and QPI35 executes. Actual605/30103 yields20MHz. After the separate page-word change it recognizes8MiB at80MHz and proceeds to APM initialization. The full focused C5 suite passes318 tests including all5 local-input cases, and both workspace/native and release-WASM Clippy pass with warnings denied. These checks use explicit LTO=false and do not replace final full-workspace CI. [Combined integration receipt](../c5-psram-page-2026-11-24/integration-checks.json) retains exact source/input/log hashes, commands, intermediate boundaries and limitations.
