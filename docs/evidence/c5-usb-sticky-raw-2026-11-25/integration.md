# C5 original factory reaches app_main after USB RAW integration

The unchanged LCD2.73 ROM/factory now executes real tick interrupts and reaches `app_main` at `0x4200aebe`, nominal cycle 38,867,584. RTC and QMI8658 initialization are logged. The next stop is `0x40800db0`, writing `0x00000003` to MODEM_LPCON `CLK_CONF` (`0x600af018`). LCD output remains zero and the SD transport has received no command. This is a source checkpoint, not product acceptance or a publication result.

The [receipt](integration-checks.json) pins all source/input/log hashes and reproduction commands. All 541 C5 cases pass, including all six supplied-input cases, with no failed, ignored or filtered tests. Workspace/all-target and release WASM/jit-tests Clippy both pass with warnings denied. The run uses one Cargo build job and focused release LTO disabled; check durations are not performance measurements. Final default-LTO workspace, CPU controls, current production WASM/browser and independent product acceptance remain required.

The integrated COEX divider retains the real NUM49 request and observes the exact pre-gate XTAL48/50 ratio. The USB monitor uses the [published sticky RAW contract](README.md), distinct from FIFO occupancy: the original tick repeatedly reads RAW8 and clears SOF2 while the earlier ROM-prepared TX packet remains occupied. The observed tick cycles are 29,524,992, 31,924,992, 34,324,992 and 36,724,992. The original ordinary TG1 and TG0 watchdog enable stores are observed at 27,104,576 and 38,862,272. No host consumption, SOF event, forced interrupt, PC jump, firmware patch or host-rendered frame supplies this continuation.

Exact USB monitor accesses require known APB/PLL48 and an unchanged named cold PCR clock/reset configuration. Unsupported control, unknown clocks and partial writes retain strict refusal and old-watchdog handling. Plain/UnitCost SRAM fixtures cover both a pristine and a sealed FIFO, CSR/destination preservation, retention/reset and unsupported requests. These small fixtures are separate from the original-firmware run. A read-only native diagnostic observes latch/FIFO/clock state after stop; it does not advance time or change MMIO.

Earlier negative evidence remains intact. The first new fixture incorrectly assumed an existing mandatory PLL48 gate could be closed; only that fixture was corrected. The prior conservative USB owner passed 540 cases but stopped at the first tick because any previous TX made whole RAW unknown. Pure state and actual early ROM TX probes isolated that boundary. The C5 SS/SC/WTC source contract then justified a stronger sticky-history invariant, and the old implementation fails the new component regression. The original owner receipts, capture hashes and three independent source-only review hashes remain in the receipt; no prior result is rewritten as success.

The latest UART contains SHTC3 wake/read failures; the later printed `0x2638` is not a genuine ID response. Wi-Fi initialization then requests COEX and Wi-Fi power clock gates. Value3 means COEX_EN bit1 plus WIFIPWR_EN bit0, with I2C_MST_EN bit2 clear. The 160MHz source mux remains SYSCON+04 bit12. Neither this request nor the earlier pre-gate divider supplies RF readiness. The strict owned CLK_CONF fault classification and gate support remain pending at this checkpoint.

Only compact facts and hashes are committed. Private raw captures, complete UART/register/test streams, SDK listings and original binary inputs remain outside Git. No original input, historical raw-log hash, golden output or public C5 support claim changes.
