# 产品、模块与固件入库

使命：让 agent 能配置和测试产品，让人能操作产品，并能嵌入任意网站。外观、元信息、模拟行为和真实硬件验证分别交付，不以漂亮模型代表固件兼容。

先读仓库 `AGENTS.md`、`docs/platform/README.md` 和现有同类条目。正式条目通过 PR 贡献；私人 DIY 定义允许单独导入、导出和分享，不自动进入主库。

## 资料与知识库

- 先确定厂商、SKU、硬件版本；版本未知就明确记录，不能把相近产品或不同版次的引脚混用。
- 实际访问官方产品页、datasheet、原理图、尺寸图、固件仓库和结构件目录。产品介绍、技术参数、接口与引脚、电源、芯片、屏幕、存储、传感器、尺寸重量均保留来源；缺项写未知。
- 每个实际抓取的来源记录原始 URL、最终 URL（如重定向）、UTC 抓取时间、媒体类型、字节数及 SHA-256。仅发现的链接标为 `linked`，不能虚构抓取时间或校验值。保留历史资料版次，不以本次时间掩盖旧资料。
- 产品元信息是供其他 agent 读取的知识库：结构化事实带单位、依据和 `sourceIds`，提供静态索引与原始 JSON 链接；简介自己概括，不整页复制。
- 按 [knowledge.md](references/knowledge.md) 组织事实和来源。区分官方标注、CAD 测量、照片测量、未知，也区分事实和本平台支持程度。

## 产品与模块的 3D 模型

严格按以下优先级选来源：

1. **厂家公开的现成 CAD / 3D 打印文件优先。** 核对 SKU、版本、单位和授权，固定仓库提交及文件 hash；检查是否为爆炸图、打印排版、壳体单件或完整装配。保留原始坐标与装配变换，不能将整包文件强行缩放为产品外形。

   产品目录没有单独 STEP 时，还要检查官方链接的 KiCad footprint：`.kicad_mod` 可能包含 `embedded_files` 中的 STEP。按对应 KiCad 版本格式解码、解压并校验，分别记录原始 footprint、内嵌 STEP 与导出几何的 hash，保留 footprint 中的 offset/scale/rotation。读取 STEP 时同时检查实体和开放曲面，避免漏掉 USB 金属壳。真实 PCB CAD 与空白 UNKNOWN 占位分别标识；裸板没有外壳时不能把第一个 PCB 零件当成可改色外壳。
2. **没有合适模型时，用公开照片、尺寸和标准件建模。** USB Type-C、Type-A、Grove 等优先复用厂家或可信来源的准确零件；记录具体型号、尺寸和许可，不拿近似连接器偷偷当尺寸基准。摆到与照片一致的视角进行 1:1 对照，不能凭模型记忆补外观。
3. **高清照片可裁切并校正后用作纹理。** 保留原图来源、裁切区域、透视变换和 UV 映射，避免将阴影、反光或透视误差烘焙成结构。静态产品照片不得覆盖真实固件画面。

照片里的灰色塑料、金属、孔洞、阴影不能当成白色贴纸。先分离纸贴与外壳，用透明遮罩保留真实印刷边界；避免把背面照片投射到内部卡扣、孔壁或不同高度的面。没有对应承载面的 CAD 时，按照片与尺寸建立独立薄贴纸面，记录位置依据与估算。必须分别检查原厂色、金色和半透明紫色：外壳随材质变化，纸贴、屏幕、键帽和连接器保持各自材质。检查孔洞与近乎侧面的视角，不能只以轮廓相似度验收贴图。

按 [model-verification.md](references/model-verification.md) 完成尺寸、同视角叠图及交互三类验证；未通过就列出偏差，不写“精确还原完成”。保留可重新生成的源文件和导出脚本。网站展示优化后的本地资产，不依赖第三方 3D CDN。

复现仓库内已有的通用模型时，先运行 `python tools/rebuild-product-model.py plan <product-id>`，再按 `docs/platform/model-reproduction.md` 在独立 scratch 目录重建。默认仅使用已提交、hash 匹配的原始资产；缺少原图时才显式启用网络并核对固定 hash。不要依赖旧批量导入脚本的私有队列或临时下载目录，也不要直接覆盖现有验收证据。

### 内部零件、PCB 占位与后续升级

- 原理图说明电气连接，不能代替 PCB 布局、元件坐标或板级 CAD。先查厂家 PCB 工程、Gerber、装配图、板级 STEP 及拆机照片，记录找到和缺失的资料。
- **没有 PCB 数据时，制作空白 PCB 占位模型，板面清楚标注 `UNKNOWN`。** 仅添加公开照片或 CAD 能确认的外观可见端子/连接器，不猜测内部元件、丝印、焊盘或走线。这样爆炸图仍保留主板这一层。
- 板形、厚度、开孔和装配位置有证据就按证据建模；没有证据的尺寸可以依据外壳内部空间估算，但必须逐项标为估算，不能写成官方尺寸。使用中性的占位外观，不暗示已知真实板色；半透明外壳下也须能识别 `UNKNOWN`。
- 给 PCB 和连接器保留稳定的语义 ID、局部坐标系与装配锚点，区分 `placeholder`、照片推算与厂家 CAD。以后取得数据时替换对应资产并更新来源和验证报告，保留兼容的零件 ID；坐标变化则显式迁移锚点与爆炸方向，不能让旧配件悬空。
- 爆炸图按零件/装配组声明原位变换、分离方向、距离和层级。占位 PCB 可以参与展开与复位，但不计入内部 1:1 验证通过项；未知内部结构不能通过中心发散动画变成“已还原”。具体规则见 [model-verification.md](references/model-verification.md)。

## 模块行为与固件

- 产品定义声明屏幕、按键、触摸、接口和电气参数；模型提供对应交互区域。模块定义区分物理接线、逻辑注入与仅外观。没有实现行为的接口仍可进入知识库，但不能称作已模拟。
- **每台设备都必须调查官方出厂固件。** 检查该型号及硬件版次的官方产品页、出厂程序/恢复说明、源码或 Release，以及官方 M5Burner 条目；保留来源与抓取时间，并为每台设备留下找到、仅资料入口或本轮未找到的调查记录。不能用“支持 UIFlow”、通用 MicroPython 或第三方适配项目冒充出厂固件；官方项目也只有来源明确证明其出厂用途时才能标为 `role: factory`。详见 [firmware.md](references/firmware.md)。
- **找到固定版本的官方出厂条目后，将它排在该设备固件列表第一项，并将产品 `defaultFirmwareId` 指向它。** 首次进入和切换设备时 UI 直接选中第一项，无须用户再选一次；分享配置或用户明确选定的其他固件须保留。记录版本、发布出处、远程地址与可获得的 hash；未公开镜像、缺少启动文件或未找到来源须明确记录，不能虚构 URL/hash。若尚不兼容，保留限制和试运行标签，不换成诊断程序冒充官方体验。
- 同时调查该具体型号的官方 UIFlow 与小智固件，加入精确项目/设备映射的 watchlist，保留 factory-first/default。新版官方 M5Burner 的字符串项目、设备与固定版本 ID 可作为无发布方 SHA 的自动更新依据；仅此 provider 适用，来源身份和版本分支须严格核对，新版始终为未验证 trial，不能虚构 hash 或继承旧验证。详见 [firmware.md](references/firmware.md)。
- **未验证不等于禁止尝试。** 目标产品有板级模型且镜像完整时，使用 `status: trial`、`simulationVerified: false`，提供“下载并尝试运行”，与用户本地固件走同一加载链路；芯片、hash、容量和布局检查仍须通过。没有可启动镜像才是 `reference`，没有板级模型则隐藏运行按钮，显示红字“尚未完成适配”。未验证固件不常驻大段警告，点击运行后弹出确认，取消时不下载；已验证固件直接运行。工作台与 mini 行为一致，agent API 保持非交互。执行按钮旁提供“报告问题”，预填型号、固件、错误和脱敏后的近期日志，只打开 GitHub issue 草稿，由用户补充描述并提交。不能把尝试运行标成兼容通过，也不能以下载到磁盘替代运行。逐固件启动或完整功能验收不是入库和试运行的前置条件；用户要求只整理资料或暂停固件验证时，完成目录、来源和静态检查即可，不自行扩大运行测试。
- 按官方文档建立按键/触摸行为用例，验证固件画面或串口结果。3D 按钮支持按下、按住、释放、组合键与键盘映射；失焦/切换时释放输入。电源键若由独立控制器处理，不当作普通 GPIO 或用前端动画假装关机。
- 键盘须逐键建立稳定 ID、实际物理行列及厂家扫描映射，核对照片字符与官方源码。从原厂 CAD 分出键帽时保留原坐标和全部三角形，检查每个键帽的最近射线命中；键帽、纸贴和外壳材质分别处理。鼠标、电脑键盘、agent 与录制回放走同一矩阵输入，不以 UART 文本代替按键。默认映射中的平台约定（例如 Fn）要明确标记，不能冒充硬件定义。
- 鼠标悬停提示使用轻微半透明光晕：**可交互部位绿色，可拖拽旋转表面蓝色，触摸屏幕红色**。只高亮当前命中的可见部位，不穿透外壳操作背面按钮；自定义外壳配色不能改变提示色。
- 外部连接器须提供有来源的插口锚点、朝向和接口标识。插头和线缆从该插口延伸，检查旋转后的连接位置、插接深度和两端连接，不能从外壳中心或任意边缘出线。视觉插接成功不等于电气路由已模拟。
- **每个接口分别核对线序和插合。** 记录插口局部坐标、口沿平面、朝外法向、逐脚颜色/信号及来源；明确照片是正视、背视还是插头线侧，检查镜像关系。禁止继承通用默认线序。按该型号背贴、原理图与可见端子交叉核对；资料冲突保留冲突，未核实则禁止显示已连接线缆。插座必须有中空插入空间，暗色照片不能变成封口黑块；插头前端进入插座、止挡留在外部、线从真实出线位置离开，检查两端和旋转后的姿态。隐藏深度估算须明示，不冒充精确装配 CAD。见仓库 `docs/platform/grove-connectors.md`。
- 固件采用远程链接，第三方二进制不镜像到本站服务器或 Git 仓库；允许在用户自己的浏览器持久缓存，按 URL + SHA-256 区分并在读取时复核 hash，提供清理入口。记录版本、目标芯片/产品、Flash 布局、来源及校验值。知名项目不代表已兼容。
- 分类 watchlist 追踪已知项目发布源；按设备、发布渠道与镜像格式匹配新版本，发布 Pages 前或手动 Action 更新目录 JSON 中的版本、远程链接和发布源 SHA-256。新版本重置为 trial，不继承旧版验证；缺少唯一匹配或 hash 则保留旧版本并记录原因。按 [firmware.md](references/firmware.md) 执行，不下载镜像到服务器，也不自动运行或刷机。
- 工作台和 mini 嵌入页都应有用户主动点击的刷机入口。Web Serial 串口选择来自用户手势；先核对设备与镜像再写入。URL 返回 404/410 时给出可复制诊断和预填 issue 链接，不擅自提交 issue。
- 分享可携带操作记录；记录按键语义和触摸轨迹，不记录或回放刷机。明确初始状态、固件 hash、时序基准和停止条件，回放后验证固件输出。有效的分享场景默认自动加载并启动，有录制则自动回放；未验证固件仍先确认，未适配设备不运行。支持 `autostart=0` 只预览、`autoplay=0` 只启动不回放；不自动刷机或清空设备/TF 数据。

## 验收与交付

1. 验证目录、知识记录、scene schema 与来源引用；安装 `tools/requirements-catalog.txt` 后运行 `python tools/validate-platform-catalog.py`，再运行与改动有关的 `tools/platform-*-test.mjs`。新增行为测试验证实际边界和结果，不只匹配字段名或照抄实现。
2. 产品/模块：执行尺寸和照片对照，检查正反侧视、屏幕与按键交互、三种悬停颜色、配件插口、2D/3D 切换、模型加载失败回退，以及独立窗口与 iframe 的分享还原。自定义透明/配色模式用独立用例检查，1:1 照片验收仍使用官方外观；占位 PCB 始终标记 `UNKNOWN`。浏览器遵循仓库生命周期约定。
3. 固件：核对每台设备的出厂固件调查记录、列表第一项与 `defaultFirmwareId`，并验证目录、来源和可用镜像的 hash/芯片/布局。只有当前任务包含运行验收时，才在已实现的板级模型执行并观察串口和真实 framebuffer；未运行仍可作为 `trial` 提供尝试，不能写成兼容已验证。链路测试区分坏链接与 CORS 错误；没有硬件测试时明确写“未实机验证”。
4. 提交来源清单、知识记录、模型/纹理授权与变换、验证报告、已知偏差和复现实验命令。测试报告必须对应本次最终资产 hash。不要把生成图当参考照片，不把视觉相似度当固件测试通过。

已有示例：`web/platform/knowledge/m5stack-stopwatch.json`；运行 API 见 `skills/esp-online-tester/SKILL.md`。新资料若与示例冲突，以可核验的一手资料为准，保留冲突说明。

### 可输出配件的行为验收

- RGB/蜂鸣器等输出配件必须由真实客体外设输出驱动；只改前端颜色或播放动画不能算行为适配。U003 的现有路径为 StopWatch Port A 黄线 G10 → RMT → 三颗 SK6812；不得将它套用到其他 RGB SKU、白线或串级出口。
- 分别验证正确引脚、错误引脚、断电、拔插、客体重启及平台重启；恢复供电不能凭旧界面数值冒充新的器件输出。共享与 mini 使用同一路由。
- 原理图链序不等于 PCB 空间位置；没有元件布局或实机逐灯证据时，明确标注 3D 灯孔顺序尚未校准，同时保留真实链序数值。

### 模拟电压与旋钮配件

- 先核对原理图、信号线颜色、主机 ADC 引脚和供电。输入位置必须经过电路模型及真实 ADC 寄存器转换；不能把 UI 数字、串口文本或直接覆盖 ADC 返回值当作适配完成。
- 厂家公式、原理图或版次冲突时，明确命名采用的标称曲线并记录冲突；机械显示行程、旋转方向与电气传递曲线分别说明是否校准。不要把编码器步数当作电位器模拟电压。
- 验证错通道、断电、拔插、两种重启和回放。暂停输入规则沿用平台合同；供电时标称电压和固件实际转换读数须分开展示。公开重建工具应保留旋钮等派生几何所依据的全部已校验参考照片。

### 分线器与连接拓扑

- 被动逐脚并联、I²C 多路选择器、MCU 扩展器必须按真实电路区别建模。分线器不会增加 GPIO；分别验证端口占用、同信号争用、断开上游与单个子口、供电、重启及录制。不能用逻辑注入伪装实际连接。
- 并联网表不能证明每只插座的三维 pin1 方位；接口按照片键槽、逐针标注和 PCB/连接器资料分别核实。方位未确定的出口不显示已连接线缆，同时保留已证实的电气网表与未知项。U006 当前示例仅支持一层、已适配的不同信号器件；未知拓扑显式拒绝。

### I²C 环境传感器配件

- 同系列不同 SKU 可能使用完全不同芯片；核对地址、上拉、电压及主机 SDA/SCL 矩阵，不以同名 ENV 或旧款 CAD 代替本型号证据。复用相关壳体须标清原 SKU，再按目标型号尺寸图和照片检验。
- 环境输入应改变真实传感器协议状态，保留忙状态、CRC、校准寄存器和客体补偿链。使用厂家驱动或独立公式核对客体读数，不以 API 回执或界面参数当成固件输出。
- 逐项检查错误针脚/地址、断电、拔插、复位及回放；I²C 分线器并不消除地址或 GPIO 争用。公开虚拟串号/校准向量、简化时序和未实现加热等边界，不称作真实器件标定。
