# 远程固件、watchlist 与刷机

目录提供可选择的已描述固件；watchlist 按品类追踪项目，例如多功能工具、MicroPython/可视化编程、显示终端、定位/传感器。每项有 id、项目主页、官方发布源、目标芯片/产品、版本、检测时间和状态。没有当前产品兼容证据的固件只供发现，不默认可运行或可刷。

前台统一使用按当前设备 `productIds` 筛选的固件库，不再提供独立的通用知名固件选择器。通过 `watchlistId` 关联发布源与版本检查；`publisher`、`role` 区分厂商出厂固件和适配项目。`defaultFirmwareId` 指向产品的默认官方出厂条目。硬件已有适配但模拟未验证的项目可以收录为资料条目，明确不可运行，不能因同为 ESP32 就列为该产品兼容固件。

定时 Action 使用认证后的官方 release API 同步发布元信息；浏览器读取本站的版本快照，显示同步时间、过期和失败状态，避免共享出口 IP 的匿名 API 限流。此流程只保存元信息，不镜像二进制。更新程序支持限流、超时；检查远程 URL，HEAD 被拒绝时有限 GET，不下载完整固件入库。区分新版本、有效、404/410、限流、服务器异常与暂时未知。CORS 不能伪装成 404，GitHub API 可读也不意味二进制允许浏览器跨域。

没有 GitHub Release、但已收录于官方 M5Burner 的固件可使用 `metadataProvider: 'm5burner'`。固定官方元信息接口和该固件的 `firmwareId`，仅从已发布版本中按发布时间选择最新项；保存版本、日期与官方 CDN 链接，不能保留作者账号等无关资料。GitHub 令牌只发给 GitHub，不传给 M5Burner。用 `tools/sync-firmware-release-metadata.mjs` 生成静态快照；查到新版本后仍须单独核对完整镜像 hash 和实际运行，不能自动把新版本替换成默认固件。

产品提供官方固件时默认选择该官方条目。浏览器直载失败先检查发布者提供的官方 CDN 或安装器使用的官方源；平台白名单、`no-cors`、Service Worker 或 Action 都不能赋予浏览器跨域读取权限。Action 可检查发布元信息，不能下载镜像后转存为本站固件。未找到允许跨域的官方源时展示官方下载/刷机页，并明确本站暂不可直载。

替换下载地址前须把候选完整下载到内存核对 SHA-256。同版本、同大小仍可能是不同构建；应分别收录和固定 hash，不互相冒充。动态 `latest`/`release` 地址只有配合固定 hash 才能作为该版本来源，内容漂移时拒绝运行/刷机，重新核验版本。区分 app、merged/factory 与多设备 ZIP；能跨域读取不意味着镜像完整或产品兼容。

开发诊断与 Hello fixture 留在仓库测试定义中，不放入用户产品/固件库。发布 Pages 前通过 `tools/stage-platform-pages.mjs` 排除内部 StopWatch 诊断清单与二进制，测试先运行，发布再筛选；线上验证这些路径不可下载。

本站服务器及 Git 仓库只存第三方固件链接与元信息，固件由用户浏览器直连官方来源。允许在用户浏览器用 IndexedDB 持久缓存已校验且固定 SHA-256 的远程二进制；缓存键包含 URL 与 hash，命中后重新校验，错误数据丢弃重下。浏览器存储不可用时降级为内存；限制总容量并淘汰旧项，提供明确清理入口。未固定 hash 的可变地址不能长期复用旧数据。已有第一方诊断固件和上游测试 fixture 保留原用途。固定版本 URL 和 hash 优于可变 latest，新版本需重新验证，不能继承旧版兼容性。

坏链接界面提供 URL、HTTP 状态、检查时间及预填 issue 链接，只建议用户提交，不后台发 issue，不发送令牌、串口标识或带凭据 URL。浏览器/网络失败可复制错误详情。

工作台和 mini 页共用刷机实现：安全上下文、支持 Web Serial 的浏览器、用户点击选择串口。嵌入页说明 allow="serial" 和父页 Permissions Policy 限制，受限时可打开独立页。物理刷机不暴露为共享录制事件或无需用户手势的 iframe 消息。

模拟页面的“下载并运行”由用户点击后依次加载并启动；分享链接不自动执行。下载进度来自实际读取字节，可比较的总长度已知时才显示百分比，未知长度或压缩后长度不可比时用不定进度；校验和准备阶段单独标记。取消、失败或切换场景后不得再显示旧请求的进度。API 的 `loadFirmware()` 仍只加载，由调用方决定是否 `start()`。

写入前核对芯片、Flash 容量、镜像完整性、目标产品和偏移/分区；不能把 app.bin 当 offset 0 完整镜像。只写声明区域，不默认全片擦除。报告下载、连接、检查、写入、校验、重启进度。取消/断连后释放端口，说明可能已经部分写入，不宣称可回滚。

测试分别列：元信息/404/CORS、内存下载/布局校验、注入串口替身的协议测试、真实硬件测试。没实际写设备就标“未实机验证”，替身测试不能证明实芯片可启动。

运行入口与版本发现须分开判断。找到最新固件不代表该设备的板级模拟器已就绪；未实现时保留禁用的“下载并运行”按钮，并在按钮旁直接显示设备名和不可运行原因。不要把此按钮替换为浏览器下载文件，也不能用其他设备或诊断固件代替运行。

本地文件按内容识别：完整 merged 镜像可直接加载；app.bin 提示继续选择 flasher_args.json 及其列出的 bootloader、partition table 等文件，也可选择整个构建目录。清单决定每段偏移，检查芯片、容量、路径歧义、缺文件和重叠，不能按文件名猜布局。所有本地文件只在当前浏览器读取。

设备写入数据与固件下载缓存是两类存储。设备数据按产品型号、板级模型、芯片和实际初始 Flash 内容 hash 隔离；不要使用文件名、路径或可变 URL 作为固件身份。软件重启、界面重启以及同固件重新加载后应保留写入；不同设备或不同固件不得串用。提供“设备存储”手动清空当前作用域的入口，还原初始镜像并停止运行，不能顺带清其他固件的数据或下载缓存。验证必须包含真实 Flash 写入→重启→读取，并检查刷新恢复、跨固件隔离、清空及多页冲突；存储不可用须明确提示。不得把用户私有文件、存储快照或其中的配置提交到仓库、分享链接或第三方服务。
